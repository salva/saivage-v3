# Design: F01 — port v2 design tokens to v3 (CSS pipeline)

This is the first of five linked proposals that port the Saivage v2 visual style and conversation rendering into v3. Process the proposals in lexicographic order — each later one depends on the previous batch having merged.

The canonical, dual-LLM-vetted documents live under `SPEC/2026-05/review-ui-port-from-v2/F01-design-tokens/`. This file is just the mailbox entry that points the harness at them.

## Problem

v3 has no global stylesheet — every component scopes its own CSS and hard-codes ~50 distinct GitHub-dark hex literals. v2 has a four-layer pipeline (`tokens.css → semantic.css → base.css → patterns.css`) whose semantic variables (`--surface-1`, `--entry-user-bg`, `--syn-key`, …) drive the entire UI. Without this layer the F02 hierarchical components, F03 round rendering, F04 chat surface, and F05 tool chips have nowhere to draw colors/spacing/typography from.

## Decision

Implement [F01 02-design-r2.md](../SPEC/2026-05/review-ui-port-from-v2/F01-design-tokens/02-design-r2.md), which is the converged, reviewer-approved design. Read [01-analysis-r2.md](../SPEC/2026-05/review-ui-port-from-v2/F01-design-tokens/01-analysis-r2.md) for the v3 hex-audit table and v2-variable diff. Read [03-plan-r2.md](../SPEC/2026-05/review-ui-port-from-v2/F01-design-tokens/03-plan-r2.md) for the executable step list, including the exact grep gates and visual diff matrix.

Binding contract:

- Single batch, single commit. No temporary dual visual system, no `--legacy-*` aliases.
- Port v2 styles **verbatim** into `web/src/styles/{tokens.css,semantic.css,base.css,patterns.css}`. Aggregate from `web/src/styles/index.css`. Import once from `main.ts`.
- Re-derive the dark palette from v3's existing hex audit (analysis §3.4). Variable names match v2 exactly; values are dark-mode.
- Add `web/src/styles/highlight-overrides.css` to win the `pre.hljs` shell only; `github-dark.css` keeps the `.hljs-*` token colors.
- Mechanically replace every in-tree raw hex with the correct semantic `var(...)`. `semantic.css` must contain **no** raw hex (only `var()`, `rgba()`, `color-mix()`).

## Files to change

The plan is the authoritative file list. High-level summary:

- Add `web/src/styles/{tokens.css,semantic.css,base.css,patterns.css,highlight-overrides.css,index.css}`.
- Modify `web/src/main.ts` to import `./styles/index.css`.
- Modify every component currently using raw hex literals to use semantic `var(...)`.

## Files / tests / docs to delete

None in this batch beyond inline hex literals replaced by `var(...)`.

## Validation gate

Run from `/work/saivage-v3`:

1. `pnpm -C web typecheck`
2. `pnpm -C web test`
3. `pnpm -C web build`
4. Grep gate: `! grep -rE '#[0-9a-fA-F]{3,8}\b' web/src --include='*.vue' --include='*.ts' --include='*.css' --exclude-dir=__tests__ | grep -v 'web/src/styles/tokens.css'` must produce no matches outside `tokens.css`.
5. Restart `saivage.service` is NOT in scope for the harness — leave the dev server alone. Verify visual diff via Playwright MCP smoke against `http://127.0.0.1:8090` on the surfaces listed in `02-design-r2.md` §visual matrix.

## Risks / accepted residuals

- `--text-faint` is borderline AA on `--bg`; analysis r2 constrains usage to large/UI-only. Operator has accepted this.
- Single-batch landing means a brief window during the commit where un-replaced hex would fail the grep gate; the gate IS the safety net.

## Out of scope

- Pattern-class adoption in components (owned by F02).
- ToolChip / Conversation primitives (F02 + F03 + F05).
- Chat surface decomposition (F04).
- Any backend change.

## Architecture rule

`ARCHITECTURE-FIRST, NO BACKWARD COMPATIBILITY`. The harness must not introduce alias variables, fallback styles, or temporary dual systems. If the design seems to imply one, treat it as a bug in the design and file a delta-proposal mini-cycle.
