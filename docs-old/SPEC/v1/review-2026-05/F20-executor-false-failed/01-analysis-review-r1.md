## Design

The design adds `needs_verification -> running`, `needs_verification -> done`, and `needs_verification -> failed` to `VALID_TRANSITIONS`, but then says the only F20 state-machine action is `running -> needs_verification` and the resume path is deferred. Either implement an owned F20 action sequence for resume and verification resolution, or remove the unused edges/tests and explicitly accept that F20 creates a parked state with a named follow-up issue.

2. Align `VALID_TRANSITIONS` with the minimal architecture-first surface. The requested lifecycle is `running -> needs_verification -> {done, failed}`; r1 also adds `needs_verification -> running`, `needs_verification -> backlog`, and `needs_verification -> cancelled` while permission sets deny operator restart/cancel from `needs_verification`. Require the design to either justify and wire every extra edge through a concrete action/permission path, or shrink the transition row to only owned, tested edges.
