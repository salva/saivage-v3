## Design review

1. Reject Proposal A as the chosen path under the project guideline. It leaves the `update()`/`mutateCard()` split, leaves shared index/dependency cache writes, and explicitly defers silent untracked mutations. It is useful as a contrast, but the design document should mark it as rejected for architecture-first/no-dead-code reasons rather than presenting it as a viable focused fix.

2. Remove B.2 as a viable variant. Keeping `cards/index.json`, `depends-on.json`, and `blocks.json` as caches preserves the old redundant layout that F13 identifies as defective. Under the no-backward-compatibility rule, the only acceptable level-up design is to delete those authoritative/cache files and derive graph/dependency state from by-id cards.

3. Fix the locking model before implementation. A per-card lock is not sufficient while mutations still write shared files such as `cards/index.json`, `depends-on.json`, and `blocks.json` ([src/cards/card-store.ts#L857-L869](../../../src/cards/card-store.ts#L857-L869), [src/cards/card-store.ts#L1042-L1051](../../../src/cards/card-store.ts#L1042-L1051)). Either delete shared cache writes before enabling concurrent per-card commits, or use a card-store-wide mutation lock until the shared files are gone.

4. Resolve the async/sync API mismatch. Proposal B says `applyMutation(id, patch, ctx): CardRecord` but also says to use `ProjectLock.withLock`, which returns `Promise<T>` ([src/persistence/project-lock.ts#L60-L105](../../../src/persistence/project-lock.ts#L60-L105)). The design must either make `applyMutation` async and convert route/tool/runtime callers, or define a synchronous retrying lock primitive. Do not hide this in implementation.

5. Make crash semantics internally consistent. The design says inline write plus rollback makes orphan history unreachable, then later admits a crash between history append and by-id rename leaves an orphan. The accepted design must state one invariant: either commit by-id before history and derive history differently, or append first and fail loudly on startup when `max(history.version_seq) >= current.version_seq`. Do not both leave orphan entries visible and claim the invariant is impossible.

6. Clarify the actual source of truth. Proposal B calls history an audited single source of truth, but its read path still uses by-id as the current canonical snapshot and history as pre-mutation snapshots. Either rename the design to “single mutation entry point with audited snapshots” or define a real event-sourced/WAL reconstruction model. Avoid inventing a `CardTransaction` abstraction unless it coordinates create/update/delete and has more than one real use site.

7. Add the contract/schema decision. `CardHistoryListResponseSchema` currently accepts `z.record(...)` headers rather than typed history headers ([src/contracts/operator-api.ts#L157](../../../src/contracts/operator-api.ts#L157)). The design must explicitly choose whether to keep the wire schema unchanged or tighten it to a header schema plus full-entry schema, and then list the corresponding contract tests.

8. Complete the dead-code deletion list. In addition to the listed symbols, delete or account for `writeHistoryEntries()` after `reconcileCardHistory()` is removed ([src/cards/card-store.ts#L535-L542](../../../src/cards/card-store.ts#L535-L542)), `parseChildrenIndex()` if the children index stays unused ([src/cards/card-store.ts#L384-L388](../../../src/cards/card-store.ts#L384-L388)), `TRACKED_EDIT_FIELDS` in analyst tools ([src/agents/analyst-tools.ts#L120-L121](../../../src/agents/analyst-tools.ts#L120-L121)), schema exports/types in [src/schemas/index.ts](../../../src/schemas/index.ts) and [src/schemas/types.ts](../../../src/schemas/types.ts), and the schema tests in [tests/schemas.test.ts](../../../tests/schemas.test.ts).

9. Preserve the public broadcast event intentionally. Deleting `card_history_record_appended` is correct, but `card_history_appended` is still part of websocket/operator event contracts ([src/events/registry.ts#L58](../../../src/events/registry.ts#L58), [src/contracts/operator-events.ts#L110-L119](../../../src/contracts/operator-events.ts#L110-L119), [src/server/websocket.ts#L303](../../../src/server/websocket.ts#L303)). The design should state that runtime or route orchestration emits the public event after `applyMutation`, and include the websocket test impact.
