# F05 Plan r2 Review

## Findings

1. **B1 is not executable as a green additive checkpoint.** The plan says B1 leaves the existing `LlmCompleteOptions` / `LlmCompleteResult` / `LlmCallFn` shapes unchanged while adding the terminal-protocol and role-envelope tests ([03-plan-r2.md](03-plan-r2.md#L45), [03-plan-r2.md](03-plan-r2.md#L55-L56), [03-plan-r2.md](03-plan-r2.md#L65)). It also says `role-envelope-schemas.ts` re-exports `PlannerResultSchema`, `ExecutorResultSchema`, and `ReviewerResultSchema` from `result-parser.ts` ([03-plan-r2.md](03-plan-r2.md#L49)). Those exports do not exist today: `result-parser.ts` contains unexported `rawPlannerResultSchema`, `rawExecutorResultSchema`, and `rawReviewerResultSchema` consts ([src/agents/result-parser.ts](../../../../src/agents/result-parser.ts#L113), [src/agents/result-parser.ts](../../../../src/agents/result-parser.ts#L137), [src/agents/result-parser.ts](../../../../src/agents/result-parser.ts#L148)) and exports parser functions instead ([src/agents/result-parser.ts](../../../../src/agents/result-parser.ts#L295)). The same B1/B2 substrate also calls `zodToJsonSchema` ([03-plan-r2.md](03-plan-r2.md#L50)), but there is no existing helper under `src/`, and the package currently lists `zod` only ([package.json](../../../../package.json#L92)) with no `zod-to-json-schema` lockfile entry. An implementer cannot make B1 pass `npx tsc --noEmit` and the named tests as written. Fix by making B1 explicitly create the real schema exports/converter surface: either move/export the Zod schemas into `role-envelope-schemas.ts` in B1 and update `result-parser.ts` to import them until B3 deletes it, or add exported schema aliases in `result-parser.ts`; also add a local JSON-schema conversion helper or the package dependency/lockfile update in the same batch. If the terminal-protocol tests use the new result union before B2 flips `LlmCompleteResult`, B1 must define and use a local structural test type explicitly, because the current contract is still the old `{ content, toolCalls, finishReason }` interface ([src/agents/llm-contracts.ts](../../../../src/agents/llm-contracts.ts#L25-L28)).

2. **B2 omits the approved terminal-only request invariant and its named tests.** The approved design requires `buildLlmOptions` to filter terminal turns down to exactly one terminal tool (`terminalOnly`) and throw unless that tool is present once ([02-design-r4.md](02-design-r4.md#L106-L116)); it also states that a terminal-only turn exposes only the terminal tool ([02-design-r4.md](02-design-r4.md#L211-L221)) and that chat/Codex request tests assert `tools[].length === 1` for terminal phase ([02-design-r4.md](02-design-r4.md#L484), [02-design-r4.md](02-design-r4.md#L489)). Plan r2's `llm-options-factory.ts` spec only maps `phase` to `TerminalChoice`, rejects analyst terminal phase, and fixes `parallel_tool_calls: false` ([03-plan-r2.md](03-plan-r2.md#L83)); the B2 request-test descriptions likewise assert `tool_choice` shape but not terminal-phase catalog narrowing ([03-plan-r2.md](03-plan-r2.md#L85-L86)). If implemented literally, terminal phase can still send the full role tool catalog with a required terminal choice, violating Proposal L's request-side safety and leaving providers that ignore forced choice/parallel disabling able to emit action calls on a terminal turn. Fix by updating B2 to require `tools.filter(t => t.function.name === terminalName)` with length exactly one, use that filtered array in terminal phase, and add named tests in `llm-options-factory`, chat request, and Codex request suites that assert terminal-phase `tools[]` contains exactly the role terminal tool.

## Coverage Notes

The plan is otherwise aligned with the approved architecture-first direction: it deletes the envelope mode, removes the string flatten path, rejects legacy persisted wrappers instead of migrating them, carries `terminal_tool` through recorder/event schemas, adds green checkpoints per batch, and includes a rollback table. The B2 collapse is justified by the zero-backward-compat requirement, provided the two blocking execution gaps above are corrected.
