# F05 — Envelope-vs-toolcalls orthogonality design review r4

## Blocking findings

None.

## Approval basis

The design satisfies the approved analysis invariants and is implementation-ready. The approved analysis requires single-carrier request/result contracts, deletion of the gateway string-flatten path, one option factory, typed schema parsing instead of text heuristics, Codex support without `response_format`, no backward-compatibility shim, and matrix tests for every direct consumer ([01-analysis-r2.md#L240-L258](01-analysis-r2.md#L240-L258)). The r4 design maps those invariants directly in Proposal L and its invariant table ([02-design-r4.md#L50-L76](02-design-r4.md#L50-L76), [02-design-r4.md#L604-L616](02-design-r4.md#L604-L616)).

The provider-neutral terminal-choice split is correct. Current shared options leak the chat-completions nested function-choice shape and `response_format` into the provider-neutral type ([../../../../src/agents/llm-contracts.ts#L31-L38](../../../../src/agents/llm-contracts.ts#L31-L38)), while the current Codex request builder forwards `opts.tool_choice` verbatim and forces `parallel_tool_calls = true` ([../../../../src/agents/llm-openai-codex-gateway.ts#L105-L126](../../../../src/agents/llm-openai-codex-gateway.ts#L105-L126)). The design replaces that with `TerminalChoice` and separate chat vs Codex translations, including the flat Codex `{ type: 'function', name }` shape ([02-design-r4.md#L166-L200](02-design-r4.md#L166-L200), [02-design-r4.md#L473-L505](02-design-r4.md#L473-L505)).

The legacy wrapper migration is complete at the architectural level. The current contract still has `parsePersistedToolCalls` and the gateway flatten shim ([../../../../src/agents/llm-contracts.ts#L60-L70](../../../../src/agents/llm-contracts.ts#L60-L70), [../../../../src/agents/agent-llm-gateway.ts#L49-L58](../../../../src/agents/agent-llm-gateway.ts#L49-L58)); r4 enumerates producers, readers, web mirrors, test fixtures, parser deletions, and `LegacyMessageShapeError` rejection rather than migration shims ([02-design-r4.md#L342-L414](02-design-r4.md#L342-L414), [02-design-r4.md#L582-L603](02-design-r4.md#L582-L603)).

The `terminalTool` plumbing is end-to-end. The subsystem map identifies `invocation_succeeded` and exchange recording as observability surfaces ([../00-SUBSYSTEM-MAP.md#L175-L184](../00-SUBSYSTEM-MAP.md#L175-L184)); current schemas and recorder inputs lack the field ([../../../../src/contracts/llm-exchange.ts#L22-L30](../../../../src/contracts/llm-exchange.ts#L22-L30), [../../../../src/agents/llm-recording.ts#L47-L55](../../../../src/agents/llm-recording.ts#L47-L55), [../../../../src/schemas/event-catalog.ts#L49-L51](../../../../src/schemas/event-catalog.ts#L49-L51), [../../../../src/schemas/types.ts#L154-L156](../../../../src/schemas/types.ts#L154-L156), [../../../../src/schemas/validators.ts#L164-L166](../../../../src/schemas/validators.ts#L164-L166)). The design covers the schema surfaces and the actual emission/recorder call sites, including nullable exchange attempts and non-nullable `invocation_succeeded.terminal_tool` ([02-design-r4.md#L416-L459](02-design-r4.md#L416-L459)).

The test plan is matrix-driven and assigns ownership to the right layers: request-shape tests for gateways, validator-direct tests for terminal protocol rejection cases, adapter and analyst consumer tests, persistence/runtime/web tests, schema tests, and recovery-policy tests ([02-design-r4.md#L469-L580](02-design-r4.md#L469-L580)). That covers the direct consumers called out by the approved analysis ([01-analysis-r2.md#L99-L128](01-analysis-r2.md#L99-L128)).

## Advisory findings

1. Advisory: the legacy grep count and capability-axis wording are stale, but not architecturally blocking.
   - What is wrong: Section 6.1 says the current `toolCalls:` grep has 32 hits and that every match is itemized under the wrapper migration inventory. A fresh verification reports 33 hits. Several are capability-axis fixtures or capability requests, not legacy `{ toolCalls: [...] }` persisted wrappers.
   - Verified evidence: Section 6.1 makes the 32-hit claim ([02-design-r4.md#L346-L354](02-design-r4.md#L346-L354)). Current non-wrapper capability-axis hits include `toolCalls: 'none'` / `toolCalls: true` in [../../../../tests/agents/llm-client-integration.test.ts#L1519](../../../../tests/agents/llm-client-integration.test.ts#L1519), [../../../../tests/agents/provider.test.ts#L276-L281](../../../../tests/agents/provider.test.ts#L276-L281), [../../../../tests/agents/agent-adapter-recovery.test.ts#L131-L132](../../../../tests/agents/agent-adapter-recovery.test.ts#L131-L132), and [../../../../tests/agents/model-router.test.ts#L527](../../../../tests/agents/model-router.test.ts#L527). The design already schedules the capability-axis swap separately in step 12 ([02-design-r4.md#L594-L595](02-design-r4.md#L594-L595)), so this is count/wording drift rather than a missed wrapper migration.
   - Required change: none before approval. Before implementation or while executing step 12, update the grep count and broaden the capability-axis fixture wording so it covers all `toolCalls` capability/request forms, not only `{ toolCalls: 'native' }` examples.

2. Advisory: validator ownership wording slightly overstates the terminal-arguments parse boundary, but the implementation shape remains sound.
   - What is wrong: Sections 4.2 and 4.3 say all six rejection cases are owned by `validateTerminalProtocol`, while the sixth case-family (`terminal_arguments_not_json` / `terminal_arguments_schema_mismatch`) is explicitly raised by `parseRoleEnvelopeArguments` after `validateTerminalProtocol` returns.
   - Verified evidence: The single-owner claim appears at [02-design-r4.md#L226-L257](02-design-r4.md#L226-L257), while case-family 6 and the parse function boundary are specified at [02-design-r4.md#L270-L296](02-design-r4.md#L270-L296). The test plan also correctly splits exclusivity tests into `terminal-protocol.test.ts` and parse-boundary tests into `parse-role-envelope-arguments.test.ts` ([02-design-r4.md#L507-L527](02-design-r4.md#L507-L527)).
   - Required change: none before approval. A future doc cleanup should phrase this as: `validateTerminalProtocol` owns terminal-call exclusivity and role/name checks; `parseRoleEnvelopeArguments` owns terminal argument JSON/schema validation, still inside the adapter boundary and before result acceptance.

VERDICT: APPROVED
