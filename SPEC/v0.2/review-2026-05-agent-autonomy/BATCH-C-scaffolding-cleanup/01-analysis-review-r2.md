# Batch C Functional Analysis Review

## Findings

No blocking findings. The r2 analysis substantively addresses the r1 objections and is ready to feed the design phase.

1. **Budget composition is now internally coherent and aligned with the brief.** The analysis separates free agent turns, same-conversation contract repair rounds, and transport-class wrapper retries. It explicitly says contract mismatches, free-turn exhaustion, and repair-round exhaustion must not trigger whole-`agentFn` replay, which matches the verifier-with-repair-loop model in the redesign brief. The current-state table remains source-backed: `contract_mismatch` is classified as `fail_invocation` with `abort=true` in [src/agents/invocation-recovery-policy.ts#L127-L128](../../../../src/agents/invocation-recovery-policy.ts#L127-L128), the adapter throws on abort at [src/agents/agent-adapter.ts#L447-L450](../../../../src/agents/agent-adapter.ts#L447-L450), and the outer wrapper retries whole invocations via [src/agents/recovery.ts#L97-L174](../../../../src/agents/recovery.ts#L97-L174).

2. **Candidate-chain freshness is no longer frozen into the invocation plan.** R1's stale-chain concern is fixed: `AgentInvocationPlan` no longer owns a candidate chain, and `CandidateResolver` is named as the authority for `router.resolve` plus the capability-skip snapshot. I spot-verified the current source anchors: pre-flight resolve at [src/agents/agent-adapter.ts#L234](../../../../src/agents/agent-adapter.ts#L234), per-outer-attempt resolve at [src/agents/agent-adapter.ts#L269](../../../../src/agents/agent-adapter.ts#L269), and late skip reads at [src/agents/agent-adapter.ts#L243](../../../../src/agents/agent-adapter.ts#L243), [src/agents/agent-adapter.ts#L270](../../../../src/agents/agent-adapter.ts#L270), [src/agents/agent-adapter.ts#L395](../../../../src/agents/agent-adapter.ts#L395), and [src/agents/agent-adapter.ts#L431](../../../../src/agents/agent-adapter.ts#L431). The concurrency warning about router-local "last skips" is a credible cross-cutting impact, not speculative padding.

3. **The backward-compatibility smell from r1 is gone.** Section 3.4 no longer says event shapes must remain wire-compatible. It frames schemas and consumers as workspace-owned contracts that can be changed together, which is consistent with the project rule: architecture-first, no migration shims, no compatibility preservation for its own sake. The F01 target also deletes the terminal phase type, transport branches, direct `{ phase: 'terminal' }` tests, and the probe surface unless the design gives them a clean new purpose.

4. **The observability claims are now supported.** `llm_attempt` emission, schema, catalog entry, runtime event-bus propagation, and downstream uncertainty are described with the right level of evidence. Spot checks found emission at [src/agents/agent-adapter.ts#L265-L266](../../../../src/agents/agent-adapter.ts#L265-L266), schema/type/catalog anchors at [src/schemas/validators.ts#L164](../../../../src/schemas/validators.ts#L164), [src/schemas/types.ts#L160](../../../../src/schemas/types.ts#L160), and [src/schemas/event-catalog.ts#L123](../../../../src/schemas/event-catalog.ts#L123), and runtime propagation through [src/runtime/active-runtime.ts#L217](../../../../src/runtime/active-runtime.ts#L217). The revised text correctly avoids inventing an in-process runtime consumer.

5. **Minor non-blocking design note:** `AgentInvocationPlan` is described as owning the system prompt with self-check already applied, while `CandidateResolver` is also described as doing a pre-flight resolve before session creation. Current `applySelfCheck` needs a session id for event emission in [src/agents/agent-role-runner.ts#L30-L38](../../../../src/agents/agent-role-runner.ts#L30-L38). The design phase should choose whether the session is created before pre-flight resolution, or whether the plan has a pre-session capability portion and a post-session prompt portion. This is a sequencing detail for the design document, not a functional-analysis blocker.
