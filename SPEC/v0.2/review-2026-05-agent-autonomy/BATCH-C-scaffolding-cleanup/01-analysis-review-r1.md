# Batch C Functional Analysis Review

## Findings

1. **Budget target behavior is internally inconsistent and does not yet match the brief.** Section 1.2 correctly identifies the current bug: `contract_mismatch` becomes `fail_invocation` with `abort=true` in [src/agents/invocation-recovery-policy.ts](../../../../src/agents/invocation-recovery-policy.ts#L127-L132), the adapter throws on that abort in [src/agents/agent-adapter.ts](../../../../src/agents/agent-adapter.ts#L447-L450), and `invokeWithRecovery` then replays the whole `agentFn` up to `maxRetries + 1` in [src/agents/recovery.ts](../../../../src/agents/recovery.ts#L97-L174). The analysis then muddies the replacement model by saying the verify-and-repair budget is "the only budget that recovery-harness-style replay the whole agent function semantics should apply to," while the next paragraph reserves whole-candidate-chain replay for transport-class failures. The brief asks for an agent-facing structured repair conversation, not a fresh replay of the whole invocation for semantic non-compliance. Section 2.2 must make the three axes explicit: free agent turns, same-conversation contract repair rounds, and transport-only wrapper replay. If the intended design really replays the whole agent function for repair rounds, the analysis must justify how that preserves session context, candidate state, and observability.

2. **The decomposition freezes a candidate chain in one place and requires re-resolution in another.** Section 2.3 says `AgentInvocationPlan` owns the candidate chain. Section 3.1 correctly says the second `router.resolve` call must remain so candidate availability changes are picked up between recovery rounds. The source has both the pre-flight resolve in [src/agents/agent-adapter.ts](../../../../src/agents/agent-adapter.ts#L234) and the per-recovery resolve in [src/agents/agent-adapter.ts](../../../../src/agents/agent-adapter.ts#L269). A plan object can own the capability request and resolver inputs, but it cannot own a stale chain unless the design intentionally gives up that current behavior. Rewrite this part so the decomposition has one authority for candidate-chain freshness and for capturing `router.getLastCapabilitySkips()` next to the resolve that produced them.

3. **Section 3.4 contains backward-compatibility language that conflicts with project rules.** The hard constraint is architecture-first with no backward compatibility or migration shims. The analysis says event shapes "must remain wire-compatible" and that `model_repair`, `model_issue`, and `model_recovered` "must continue" to use the same `kind` strings. That is a compatibility smell. It is valid to list current consumers and semantic obligations, but the analysis should not freeze current wire shapes unless it argues they are the new clean contract. Rephrase this section around deliberate schema ownership: either keep the shapes because they are still the right architecture, or change the schemas and update consumers together.

4. **The `llm_attempt` observability claim is not adequately supported.** Section 3.4 says `llm_attempt` is consumed by the runtime ledger, then cites a runtime line that it admits is really about `session_started`. The verified source shows emission in [src/agents/agent-adapter.ts](../../../../src/agents/agent-adapter.ts#L265-L266), schema/type registration in [src/schemas/types.ts](../../../../src/schemas/types.ts#L160) and [src/schemas/validators.ts](../../../../src/schemas/validators.ts#L164), and event catalog tracking in [src/schemas/event-catalog.ts](../../../../src/schemas/event-catalog.ts#L123). I did not find a direct `src/runtime/runtime.ts` `llm_attempt` consumer. Either cite the actual consumer path, or mark this as an open audit item. As written, the cross-cutting impact section overstates its evidence.

5. **Several cited line references are stale and should be refreshed.** The file targets are generally right, but exact lines are off in multiple places. Examples verified against source: `LlmRolePhase` is at [src/agents/llm-options-factory.ts](../../../../src/agents/llm-options-factory.ts#L13), not line 14; `deriveTerminalTool` starts at [src/agents/llm-options-factory.ts](../../../../src/agents/llm-options-factory.ts#L66), not line 68; `LlmCompleteOptionsTools` / `LlmCompleteOptionsTerminal` span [src/agents/llm-contracts.ts](../../../../src/agents/llm-contracts.ts#L42-L54), not lines 43-52; and the adapter's terminal tool merge plus options build is [src/agents/agent-adapter.ts](../../../../src/agents/agent-adapter.ts#L296-L300), not lines 297-302. The analysis should refresh its tables before approval because this review dance depends on implementation-ready references.

## Axis Assessment

- **Correctness of cited file/line refs:** File choices are mostly correct, but line precision needs a cleanup pass. I verified references in `llm-options-factory.ts`, `llm-contracts.ts`, `agent-adapter.ts`, `recovery.ts`, `invocation-recovery-policy.ts`, `llm-recording.ts`, `llm-provider-gateway.ts`, and `agent-session-coordinator.ts`.
- **Completeness over F01/F08/F10:** Substantively strong. F01's dead terminal phase sites are covered, F08's real counter interactions are deeper than the inventory entry, and F10's responsibility inventory is broad enough to support design work.
- **Architecture-first / no backward compatibility:** Mostly aligned on deleting dead phase scaffolding and decomposing `invokeAgent`; Section 3.4 must remove or justify compatibility-preserving wording.
- **Self-containment:** No forbidden "as in r1" or review-process phrasing was found. The F06 reference in Section 2.3 is tolerable because the ownership question is restated in the open questions, but the next revision should avoid depending on F06 to make Batch C actionable.
- **Cross-cutting impact:** Router, recovery, session-persistence, eventBus, and observability are all named. Router and observability need the corrections above.
- **Open questions:** The document keeps real questions open, but Section 2.2 currently answers budget composition in a way that conflicts with those questions. Leave the unresolved choices open, or make the target behavior internally consistent.
- **Budget table and decomposition validity:** The current-state table is mostly credible, including the important outer replay of contract mismatches. The target budget composition and `AgentInvocationPlan` decomposition need revision before they can guide implementation.
