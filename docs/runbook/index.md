## Unavailable process evidence

EPERM during a managed-group probe or failed signal dispatch permanently revokes
that launch's numeric-PGID authority. Processes shows **Evidence unavailable**:
inspect the first redacted group diagnostic, actual leader exit/error, separate
stream open/EOF/closed facts and capture errors, plus ordinary log links. An EOF
may coexist with capture failure; leader success and closed pipes do not certify
group absence. Waits fail promptly, including with open inherited FDs. Entries and
failed scopes remain retained; repeated cleanup cannot probe, signal, forget or
transfer them to a later activation. List-query success records observation only.

Failed containment is not successful Project Stop, and can block Run or MCP owner
replacement. Service-level intervention requires separately authorized deployment
operations: stop the exact service through its deployment owner, prevent automatic
restart, and positively verify actual server/descendant absence before an authorized
restart. Follow the existing lifecycle exclusion, authentication and abandoned-lock
procedures; never erase a lock or kill a stale numeric PGID to clear this condition.
Restart itself does not certify containment of privileged descendants. Current
external absence cannot reconstruct missing historical exit, output or tool effects.

MCP unavailable evidence fences admission/readiness/catalogs and retains the failed
handle. Intentional stop or transport EOF may instead display **Process containment
failed**; neither label permits replacement. The existing roots-lifetime and
discovery-rejection procedures still apply: a distinct new explicit start after
discovery correction is allowed only following successful containment/stop join,
not after unavailable retained ownership. No automatic retry, takeover or recovery
of the original command/experiment is promised.

### Configured browser lifecycle

MCP definitions come from operator-owned YAML or agent-authored connection definitions. `mcp_server_control` starts (including
fetch/install/discovery) or stops one named configured server; `mcp_tools` returns
current exact schemas, optionally selecting toolName. Defaults admit these and
`mcp_tool_call` to Analyst/Executor; Reviewer requires explicit selection, Oversight
has none; custom card participants may opt in. Each permission is independent. Operators may
use authenticated `POST /api/mcp/servers/:name/start` or `POST /api/mcp/servers/:name/stop` with `{}`; success
is `{serverName,status,toolCount}`. Unknown names return 404, disabled/busy/changed
live entries 409, failed start/containment an error. There is no new browser UI.
An identical ready start is idempotent. Edit alone does not change a running server:
explicit stop/start loads only that entry. Other config changes still need restart.
Stop during startup closes immediately and joins; failed containment retains its
closed owner and forbids replacement. Startup autostart is preserved.

### Dynamic MCP connections

Explicitly select register/unregister/servers tools in the named agent inventory;
this adds no default grants. A typical independently authorized sequence is:

```text
mcp_server_register({serverName:"local",connection:{transport:"stdio",command:"node",args:["peer.js"]}})
mcp_server_control({serverName:"local",action:"start"})
mcp_tools({serverName:"local"})
mcp_tool_call({serverName:"local",bindingId:"<observed binding UUID>",toolName:"ping",args:{}})
mcp_server_control({serverName:"local",action:"stop"})
mcp_server_unregister({serverName:"local"})
```

For HTTP use `connection:{transport:"streamable-http",url:"https://example.com/mcp"}`.
Startup uses initialize, the initialized notification and every tools/list page
within the single 180-second start budget; it does not require HEAD support.
Rejection of the actual protocol exchange still fails start, with the existing
local containment and stop join before reporting the failure.
Registration persists only a connection in `.saivage/config/mcp-servers.json`;
it neither launches nor rewrites YAML. Duplicate names reject. Definitions survive
normal reset and host restart, but dynamic connections never autostart. Preserve
the file in complete backups; `show_config` is YAML-only and Files refuses raw
definition reads. Do not add credentials to chat examples.

`mcp_servers` explains stopped definitions, starting owners and removed owners
whose containment failed. Running means discovery complete. Fresh discovery is
required after stop/start; stale bindings fail before wire dispatch, without retry.
Unregister publishes removal before containment: on containment failure the
definition stays absent and its closed owner blocks register/start. Do not assume
failure undid removal or replay automatically; publication uncertainty is fatal
before further operations. There is no atomic replace/edit/restart tool.

Stdio `processId` is a safe shared Process observation association, not wait/kill
authority. MCP owns the runtime launch and retirement; stdout/stderr are
`not_captured`, not command output. Arbitrary process attachment is unsupported.
HTTP has null process ID; local disconnect does not terminate the external peer.
Ordinary Project Stop leaves MCP connections alive. Live catalog refresh and
card-tree visibility/lifetime remain deferred. Deployment, reset and migration
remain separate permissions; this source change authorizes none of them.

An agent start whose external discovery is explicitly rejected receives a recorded
executed failed tool result only after successful local containment and stop join.
Correct the configured server/fixture, then request a **new** start call; there is
no automatic retry, replay or historical result rewrite. Unclassified failures and
failed containment are not ordinary discovery results, and failed containment
continues to prohibit replacement. HTTP containment stops local requests/owners,
not the remote server or its effects. Authenticated REST discovery failure retains
the existing internal-failure (500) contract, not an agent ToolResult or 404/409.
Autostart discovery rejection fails startup reconciliation without readiness.

## External migrations

Saivage core and packaged utilities accept only exact current contracts: no migration,
no old-format reader, probing, normalization or compatibility fallback in runtime,
startup, init, reset, repair or ordinary deployment. Equal envelope versions do not
prove compatibility. Generic “deploy newest” encountering incompatible state stays
stopped; deployment permission is neither migration consent nor irreversible reset
consent. Same-format deployment retains valid state without a migration ceremony.
Reset is the separately consented destructive alternative; the numbered reset
branches below apply only when reset is selected and authorized. Current-format
[exact-target repair](#exact-target-offline-repair) is independent, not a converter.

Compare selected releases using the [durable format reference](../architecture/durable-format-changes.md)
**and** their actual source schemas/semantic consumers, including historical
equal-number exceptions and unknown boundaries. The reference records source
applicability, not installations or complete compatibility. Prospective discipline
belongs to [AGENTS Storage Policy](https://github.com/salva/saivage-v3/blob/HEAD/AGENTS.md#durable-format-versioning);
cumulative adoption of several changes is not permission to reuse a deployed version.

An explicit project-owner migration request supports an **external offline** operation
without per-rule extraordinary overrides. The agent chooses manual transformation or
narrow task-specific scripting under `/home/salva/g/ml/tmp/`; no proactive, shipped or
tracked reusable migration infrastructure. Follow these ordered gates:

1. Identify the exact project/service/container/workspace, source release and known
   source contracts, intended pinned release, complete generated boundary and intended
   input/release/service actions. Resolve unclear scope from release source/docs, not
   speculative startup; consult the pinned releases' format reference and actual
   semantic contracts, resolving historical equal-number exceptions/unknowns.
   Already explicit in-scope start/deployment needs no ceremonial
   reconfirmation; Run/resume and unrelated actions still need actual authorization.
2. Stop the exact service, prevent automatic restart and positively establish no
   owner/process. Maintain exclusion through cutover; live, malformed, indeterminate
   or ambiguous observations block. Exact abandoned-lock handling still needs separate
   verification/authorization, never automatic takeover or another product registry.
3. Successfully finish a complete stopped target-project backup under workspace `tmp/`
   before generated-content inspection/transformation; preserve it unchanged. Existence
   is not completion. Do not inspect descendants to choose a partial backup. Reconfirm
   owner absence before source inspection, candidate mutation and cutover unless
   continuously established. Backup is evidence, not a mutable candidate or authority.
4. Work on an independent separate complete candidate/replacement workspace outside
   original and backup. Copying canonical source state and transforming that copy,
   including historical rows/documents, or rebuilding current-format state is allowed;
   no writable aliases/hardlinks back, in-place edits or selective merges into retained
   installation roots. Cut over cards/agents/logs/work together, or the explicitly
   selected complete workspace. Preserve config/credentials/identity/operator inputs,
   prompts/skills/instructions/source/docs unless a required change is within the request.
   Follow source canonical identities, committed references and indexed history. Missing
   facts/corrupt links are blockers/limitations, not permission to invent history or adopt
   orphans. Opaque copying grants no discovery, interpretation or promotion of temporary,
   unlinked, attic or uncertain-publication contents; no generic forensic facility.
   Preserve established empty directories or derive actual target-release bootstrap
   layout, not regular files alone; genuinely lazy state stays lazy.
5. Preserve factual/history semantics wherever representable. Structural changes such
   as new selectors/IDs, renamed paths or re-encoded rows are not automatically history
   loss; describe them accurately without fabricating old effects, acceptance, producer
   provenance or events. Neither promise losslessness before evidence nor categorically
   deny equivalence: report byte-identical, semantically/history-faithful, structurally
   transformed, omitted and uncertain parts with evidence/limits. Disclose unavoidable
   concrete loss and obtain explicit confirmation before effecting that loss/cutover.
   Unresolved required provenance/representability blocks, not weakened validation or reset.
6. Pin the matching intended release and use its actual schemas/semantic consumers to
   strictly validate the **complete** candidate and linked/indexed history: card/record
   relationships/lifecycle/provenance, configured card/global sessions, segments/context/
   tool-result contracts, provider/app-log evidence, exact referenced work, configuration,
   workflow/prompt closure and required established directories. No orphan scan/certification.
   Startup/readiness alone misses historical predecessors and empty publication parents;
   do not assume init/startup is pure validation. Offline validation calls no providers/tools
   and mutates neither original nor backup. Failure blocks cutover; known construction
   mistakes may be corrected externally, then the whole candidate revalidated without overrides.
7. Under exclusion, preserved successful backup and strict validation, perform only the
   authorized complete-boundary/workspace cutover to the pinned matching release. No mixed
   roots, binary-only downgrade or multi-root atomicity/recovery guarantee. First failure
   stops; outcome uncertainty permits no artifact inspection, retry, rollback, reconciliation
   or automatic continuation. Distinguish known success from uncertainty and escalate for
   a separately scoped next operation; never selectively restore from the backup.
8. Start only if actually authorized, using the matching tested release, and verify
   separately. Health proves neither continuation, fidelity nor unchanged active chain;
   never Run/resume automatically. Preserve authentication and outbound confidentiality.
   Keep a task-local report under workspace `tmp/`, outside backup/generated state:
   request/scope, releases, preserved evidence, method, fidelity/structural provenance,
   omissions/loss confirmations, uncertainties, validation coverage/results and known
   actions. No generic ledger/schema or synthetic canonical migration event.

## Activation ownership and runtime halt

Startup admits the exact current linked card graph, consuming retained tombstones but stopping below them. It does not open old card predecessors. Missing or corrupt unconsumed card history can therefore coexist with successful readiness; a history request that reaches it still fails, without fallback or repair. Corrupt current card heads or selected documents still block startup. Required indexes, current configured sessions, provider evidence, app log and configured records retain their existing admission scope, including stopped-card streams. This admission change needs no format reset and authorizes no deployment or direct data edits.

Supervisor startup begins in internal `uninitialized`. After lifecycle exclusion, configuration, canonical generated-state admission and bound-workflow construction, composition first performs bounded configured-global settlement: Analyst, then Oversight only when its exact index is established, including disabled scheduling. A sole strict-valid final unmatched call receives a permanent uncertainty-only failed mate, without new ingress or global recovery notice; absent Oversight stays absent. Supervisor then strictly selects the complete linked running card chain and settles configured sessions then card lifecycles leaf-to-root. Only successful settlement publishes public `stopped`; startup failure leaves it uninitialized, rejects Analyst intervention, and prevents server services from returning or a listener/readiness/control endpoint from being published. Public runtime-status reads are unavailable in that internal state. Startup correction may add append-only rows and delay listener availability, but creates no activation owner, provider request, tool replay, or automatic Run. Existing broader startup/init body/evidence admission and validated tail consumption remain unchanged, including stopped-card streams; CLI init gains no global settlement. Do not confuse this process-local admission with HTTP health readiness at `GET /health/ready`.

After startup, Analyst mutation admission is derived at invocation from that one status: `stopped` and settled `paused` admit; `starting`, `running`, `pausing`, `closing`, and `error` reject. Accepted Run first installs a prepared root owner and reports `starting`; the singular ordinary halt can freeze it before launch. Application shutdown permanently closes Run admission. A lifecycle publication that becomes outcome-unknown reaches the fatal boundary and exits before Supervisor halt, cleanup, or a `closing` status. After positive dead-owner verification and explicit manual lock repair, a genuinely new process may start and settle a valid remaining running prefix before availability. A later explicit Run starts execution. The Supervisor startup/Run operation completely validates the canonical linked running set, then handles each selected card leaf-to-root by stabilizing all of that card's configured sessions and immediately publishing that card stopped before advancing. A `model_recovered` notice has no resume or redispatch authority; descendants become eligible only through later ordinary immediate-parent activation. Startup performs this correction without launching work. Same-process Stop only contains execution and leaves durable running lifecycles for the next explicit Run; Run installs a prepared root and activates only project through STOPPED. Ordinary Stop, application close, and actor-main containment continue to use the retained halt and `error` behavior. There is no separate readiness state or initialization flag.

A later normally admitted card workflow that actually selects an old configured session for activation can settle that session's one strict-valid final unmatched tool call immediately before the new activation. In an already-running fixed server, a later newly admitted explicit Analyst chat submission can likewise settle only its selected global session immediately before fresh ingress. The permanent failed result says only that effects remain uncertain; it does not prove non-execution, replay the call, resume the old activation, accept work, or append a recovery notice. An ordinary invoked-tool-await escape is already reusable after successful parked abandonment; a later explicit submission is fresh, not a replay. Only a still-poisoning failure retains the failed-session cause, so a repeated HTTP 500 alone proves neither retained poison nor repeated execution. Malformed, nonfinal, or multiple-unmatched history still fails strictly. This same-format source change needs no reset. Installing the binary alone settles nothing; a genuinely new server additionally settles a selected configured-global sole strict-valid final unmatched call before card correction and availability, without a submission, check, or active owner. No deployment or reset is authorized by this change. Do not manually append mates or edit generated history; only the separately consented [exact-target procedure](#exact-target-offline-repair) permits its named repairs. Card rollout/reactivation remains separate.

Pause is cooperative and run-scoped. Natural root completion can win from running, pausing, or paused; its stopped transition clears the old Pause request and callback before publication, so a later gate wait cannot emit paused for the old run. Project Stop and application close join one halt identity, interruption, owner snapshot, set of processor joins, and runtime-process termination. Application close additionally closes admission permanently. Concurrent callers never conflict or repeat cleanup. Retained historical Planner control-action rows remain readable, while current Planner reopen/reorder operations append no control action.

Analyst `pause_runtime` is admitted only while running and `resume_runtime` only while paused. Wrong-state requests are ordinary failed tool results so the Analyst may choose another action in the same turn; on stopped, use `start_project`, not Resume. Supervisor lifecycle checks remain strict after admission. `stop_project` is different: it always delegates and joins the existing halt, including closing and retained-error cases, and preserves the stopped/no-live no-op.

Startup correction is strict: branching/discontinuous or missing linked cards block availability before card correction; malformed complete consumed sessions also block availability. Earlier permitted tail truncations or global mates can commit before a later topology failure, so admission is not all-or-nothing. A known failure stops at its committed prefix with no rollback; no later ancestor is processed in that attempt. A valid stopped-descendant/running-ancestor prefix may be consumed by a genuinely new process after exclusion is obtained. Publication outcome unknown exits at the fatal boundary before any further read, write, halt, or cleanup. Do not repeatedly start a failed instance, inspect uncertain artifacts, manually edit canonical data, or assume lossless recovery. Use separately consented exact-target repair only where supported. A later MCP/listener failure can follow known committed correction without reversing it; a later new process freshly observes canonical state. The lock's live null endpoint means only `active lifecycle owner; runtime control unavailable`.

**Retained instructions**, **Required model facts**, and **Source and continuation**

coordinates, not original adjacency. Required facts and inherited continuation are
retained context, not new events or activation entries; current derived notices do not
prove fresh events. Between-rounds continuation is explicit. Use **Segment history**
for separate exact retained history; no stitching or current-context substitution.
Ordinary null context has no invented genesis. Inspection changes no runtime state and
shows a basis for request assembly, not the actual model request.

Ordinary first segments and compacted successors use the shared exact-target refusal and fresh-temporary/rename publication sequence, finishing segment directory synchronization before separate index replacement. This is a same-format publication alignment, not a new reset or deployment requirement. Temporary allocation/open/write/fsync/close failures are ordinary; segment rename or subsequent parent synchronization uncertainty is fatal, as for index replacement. Only successful index publication makes a segment discoverable. Unindexed segments and temporary leftovers remain ignored forever; no failure authorizes inspection, cleanup, retry, adoption, or repair.

Before startup, provide `compaction.enabled: true`, `context_utilization_fraction` in `(0,1]` (default `0.80`), `trigger_fraction` in `(0,1]` (default `0.90`), `tail_fraction` in `0..trigger_fraction` (default `0.25`), and one exact structured `summarizer_candidate: { provider, account, model }` emitted by the configured Provider Registry. Removed absolute-budget, completion-reserve, merge/summary, and escalation keys are invalid; stop the service and rewrite YAML to the current singular contract rather than expecting aliases. `account: null` means the provider-level implicit account; explicit `"_implicit"` and `"_"` remain distinct exact names. Slash-bearing model IDs are ordinary data.

For each participating route, startup binding computes `floor(context_utilization_fraction * contextWindowTokens) - max_tokens` for capacity-eligible configured candidates and freezes the largest positive result for preventive preparation. Actual primary admission measures each candidate's complete serialized request against that candidate's own result; a fitting large candidate can execute while a smaller fallback is excluded. If only the large candidate fits and becomes unavailable, normal wait/failure behavior applies—Saivage does not compact merely to restore the small fallback. Larger windows can materially increase request cost and latency. The fixed summarizer independently computes the same formula with its declared window and 2,000 output tokens (94,000 input tokens for a 120,000-token window at `0.80`). Startup checks only the invariant empty refine wrapper; actual orientation and accumulated history are admitted when used.

Startup acquires lifecycle exclusion before full selected-config/environment validation, then validates before any `--create-runtime` canonical root-card read, cards-directory creation, or initial publication. Invalid compaction configuration or unusable participant capacity releases the lock through ordinary startup cleanup and creates or changes no generated root-card state.

## Provider overload

Exact direct provider `server_is_overloaded`/`overloaded` signals retry indefinitely
with delays 30, 60, 120, 240, 480, then 600 seconds repeatedly. Bare 503/529 or
overload prose is not this policy. Contradictory auth/rate/context/policy evidence
retains its stronger classification; other failures keep finite/terminal policies.
Ordinary work can use already-admitted alternatives; overload on a policy pin
reuses only the refusing candidate and its admitted bytes, never an extra safety
reframe or model switch. A second refusal is terminal. Summary overload remains
one logical call within the 16-call/one-correction bounds, not a completed fold.

Neither overload count nor elapsed invocation time requires restart, reopen or Run.
Success is not guaranteed. Each active HTTP consumption has 120-second inactivity
and 15-minute absolute bounds; recovery waits are outside them. Stop/shutdown
cancel requests and backoff promptly. Pause is cooperative, not cancellation:
`pausing` may persist indefinitely while the admitted call retries.

Existing active execution/compaction status and refreshed provider cooling are
observations, not proof of bytes in flight, useful progress or exact next-send time.
No provider countdown or tool/child/process wait barrier is added. Attempts may
not be recorded until terminal settlement; memory evidence grows during a long
outage and interruption may lose it. Completed tools/results never replay merely
because their continuation overloads. Publication failure never triggers a resend.
This procedure explains behavior, not incident recovery or deployment authorization.

## Outbound HTTP lifecycle

The ordinary process logger emits `info` observations continuously, independently
of `--failed-provider-diagnostics`: that opt-in flag enables finite private content
captures, not lifecycle logging. Settled provider exchange evidence and those dumps
cannot show the current in-flight phase. Lifecycle metadata is not app-log Events,
API output or UI Debug, and creates no Saivage log file or durable format.

Process stdout is structured JSON by default (`NODE_ENV` absent/empty selects
production). `NODE_ENV=development` uses `pino-pretty` when available, otherwise
JSON; pretty output is presentation, not a JSONL storage contract. `LOG_LEVEL`
absent/empty defaults to `info`. Exact lowercase `info`, `debug` and `trace` enable
these `info` events; `warn`, `error`, `fatal` and `silent` suppress them. Other values
fail environment loading; there is no case/whitespace normalization or CLI level
flag. Change the actual service environment using the ordinary configuration
procedure, not an assumed live reload.

For systemd deployments, inspect the actual unit's journal. This is illustrative
read-only guidance with a placeholder, not an instruction to inspect a deployment
or a claim about its unit name or retention:

```bash
SERVICE_UNIT='<actual-service-unit>'
timeout --kill-after=2s 10s journalctl --unit "$SERVICE_UNIT" --since '15 minutes ago' --no-pager --output=cat
```

For JSON output, filter on `event` (`outbound_http_dispatch`,
`outbound_http_headers`, `outbound_http_terminal`, `outbound_http_retry_wait`), then
an exact `request_id` or `input_id` to correlate concurrent work. For example, on
an already-authorized local JSON stdout capture (which may also contain non-JSON
startup text):

```bash
timeout --kill-after=2s 10s jq -R 'fromjson? | select(.event == "outbound_http_terminal" and .request_id == "<request-UUID>")' '<local-process-log>'
```

Saivage has **no stdout rotation/retention policy**. Journald/service-manager or
operator redirection owns retention, rate limiting and possible drops. No deployed
policy has been inspected or certified for this feature. Emission is best effort:
no fsync, flush acknowledgment, retry, lossless delivery or terminal-after-crash
guarantee. A dispatch without headers/terminal shows missing observed settlement,
not proof that the request is still live, especially after restart. Log suppression
or dropping likewise cannot establish absence of requests.

Interpret the phases at the actual owner:

- Dispatch is local intent immediately before a Saivage-owned fetch, after existing
  admission/auth/pre-abort checks, not evidence of server receipt. Token reuse,
  rejected admission, pre-cancelled work and sleeping retries emit no dispatch.
  Auth refresh can dispatch and fail before any model request exists.
- Headers carry the returned numeric HTTP status and monotonic `elapsed_ms`, not
  actual headers or success. An HTTP-200 SSE failure can end with `outcome:failed`
  and `error_code:provider_failure`; it is not a completed provider response.
- Terminal describes existing response handling, before later credential/evidence/
  record publication, not logical invocation completion or known remote effects.
  `body_disposition:consumed` means EOF was read; `not_consumed` covers header-only
  owners (such as HEAD/early error handling). `cancelled_by_policy` covers metadata,
  bounded truncation and intentional parser cancellation, not user cancellation.
  `incomplete` means unfinished consumption. Outcomes/codes are closed typed values,
  never raw exception or server text.
- Retry-wait is the scheduler actually choosing to sleep, not bytes in flight.
  `delay_ms` is the selected sleep duration. Optional `deadline_ms` is the finite
  invocation availability deadline as Unix epoch milliseconds, not request
  inactivity/absolute timeout or a promised send time; overload waits omit it.
  `waiting_candidate_ref` is the hashed candidate selected for this wait, **not a
  guaranteed next dispatch**: eligibility is recomputed after waking. An eligible
  alternative can run without waiting for another candidate's backoff. A prior
  request ID/attempt index is associated where known (including refresh); a shared
  availability wait can lack a prior request. Cancellation while sleeping sends
  nothing, and there are no countdown/timer-tick events.

Coverage is provider Chat/Responses/Codex (including configured custom endpoints),
Codex/Copilot auth refresh, remote HTTP MCP initialize/initialized notification/every
tools/list page/invocation/health HEAD or conditional GET, and Websearch/Webfetch
including Analyst record preparation, metadata-only and bounded reads. There is **one lifecycle per owned
fetch invocation**, not per physical HTTP hop. Each retry and manually dispatched
web redirect gets a fresh request UUID with the same source attribution. Native
automatic provider/auth/MCP redirect hops are not individually logged; headers
describe the response returned to the owner. Native redirect behavior is unchanged.

Tool source is the initiating agent's session/input and owning card, not its MCP
server or Webfetch destination card. It stays call-local through agent-requested
MCP start/discovery, concurrent invocations, manual redirects and Analyst's
audited record-preparation closure. `source_session` projects validated canonical
identity with a SHA-256 configured-agent reference and card/global component;
`source_card` is omitted for globals, `input_id` retains a valid UUID. `model_ref`
hashes the model identity, not request content. `invocation_session` distinguishes
an internal-summary invocation from its canonical source owner. Tool owners omit
model/attempt fields they do not possess. Ownerless startup/autostart/reconciliation
and later health omit source fields; health never inherits an earlier start caller.

Only fixed service/purpose/endpoint/method labels and explicit identity/status/
timing/outcome fields are emitted. No URL/hostname/path/query/fragment/redirect
Location, credentials, headers, payload/prompts/images, tool name/arguments/results,
configured account/profile/MCP name or raw error is logged. Endpoint labels therefore
do not distinguish arbitrary custom hosts. CLI control HTTP to Saivage and browser
API/live-sync clients are excluded. Shell/package/target-program traffic, stdio MCP,
browser subresources and remote MCP peers' own external requests are not observed.

Ordinary observational sink failure preserves the transport result/error and retry
policy, without fallback logging. Publication uncertainty remains fatal before any
follow-up observation, retry, read, write or cleanup; an earlier HTTP terminal is
not evidence of successful later publication. This source-only feature changes no
discriminator and needs no state adoption/reset/migration by itself. It authorizes
no deployment, service action, provider probe or Run. Unrelated release differences
and explicitly requested external offline migrations retain their separate gates.

Current-node text remains prepared request context, not an ordinary durable model-context row; its activation marker records structural prepared-instruction evidence once. Compacted history contains nonempty `summaryText`, ordered `protectedPrompts`, and `requiredModelFacts` with two nullable recovery/refusal slots plus required descriptor-only `latestRecordObservations`, without compaction checksums or accumulated accounting. Protected durable prompts remain primary-visible in full after their covered source rows are omitted. Summarizers receive the current protected set as read-only orientation, not as independent summary intervals. Anonymous protected occurrences accumulate; an exact keyed replacement releases the older occurrence into ordinary summary source once on the next successful positive advance, or that older compactable narration may be locally omitted. Protected/prepared overhead is nonsplittable and can make compaction or admission fail; there is no quota, eviction, truncation, or universal reduction guarantee.

Compaction publishes a new immutable JSONL segment and atomically replaces its cumulative conversation index; it never appends metadata to the source segment. The new segment starts with self-contained compacted genesis carrying one accumulated summary, a variable-sized ordered protected-prompt list, two nullable bounded recovery/refusal slots plus descriptor-only latest record observations with original source coordinates/time, source version/filename/cutoff metadata, and either `between_rounds` or minimal inherited `{marker_id,input_id,active_segment_kind}` continuation. Genesis is operator context, not a transcript row or cursor. Providers receive the derived synthetic accumulated-summary context but never inherited IDs. Successful compaction over a validated atomic source prefix is the sole omission authority: uncovered summary-only/evidence-only bundles and closed rounds below the trigger remain fully visible; eligible compactable rows require successful summary construction and atomic prefix validation, while covered protected prompt rows require that same validation plus exact preservation in the ordered protected list. The predecessor remains historical and is never needed to validate, project, compact, or recover current; the next compaction inherits the accumulated summary rather than reopening it. Row omission follows append-order call/result policy authority with fixed per-surface evidence modes—mutable current discovery surfaces are observational, and only the dedicated immutable readers `get_card_version` and `read_record_version` emit canonical locators. Provider tool definitions carry no internal policy; the compiled invocation tool contracts keep it settlement-side, and exact adapter request admission measures the serialized provider request that is actually sent. Exact post-compaction recovery/refusal behavior keeps each code-owned text bounded and newest-only: the latest covered refusal locator resolves to the synthetic compacted fact and a superseded marker is no longer a current locator. The orientation and content commitments are distinct: the Analyst snapshot's complete-observation hash commits to the full strict observation even when the bounded rendering omits branches, while the content hash covers exactly the rendered bytes. Selected-graph participant reserve diagnostics report every configured agent actually participating in the selected compiled graphs, including specialized nodes. Candidate admission remains a deterministic best-effort estimate of one canonicalized complete body (`ceil(UTF-8 bytes / 4)`).

There are two exact protections for prepared configured card-node and Analyst provider turns. Preventive compaction runs before provider I/O when the prepared threshold requires it, including the initial Analyst call and every accepted or rejected-tool continuation after its canonical result and refreshed projection. Separately, exact local admission runs before turn-start and primary I/O for every ordinary route pass: each candidate is built, canonical-serialized, and capability-classified exactly once, and only admitted retained bytes are ever sent. Distinguish terminal ordinary local exact-admission failure from provider-reported context exhaustion. A local admission failure is a pre-provider configuration failure with bounded fixed capability/declared-limit/usable-input/request-size reasons, zero provider attempts for the rejected route pass, and one bounded local compaction already attempted only where at least one capability/output-compatible candidate was size-fixable; it never becomes a provider failure kind. Provider-reported context exhaustion instead has a real recorded provider attempt and at most one exact-admitted authoritative compacted retry using the retained original membership and process-local state: the context-failed member is retried first with the compacted bytes, earlier rate-limited or temporarily unavailable members and later untried members remain viable under existing scheduling, and exhausted members and originally rejected identities are never rebuilt. For an Analyst continuation, the already accepted tool effect and one canonical result are outside this provider seam and are never replayed or duplicated. A second context rejection after the authoritative retry, or a second no-fit after the one local compaction, is terminal: there is no third pass, second compaction of either kind, or route-by-compaction retry fan-out. Existing non-context routing/retry behavior is unchanged.

The byte-only candidate estimate above describes text-only requests. Image-bearing requests additionally reserve `2 * ceil(sentWidth / 32) * ceil(sentHeight / 32)` per emitted image occurrence and enforce a 32 MiB complete serialized-wire cap. Full data URLs remain in the measured/admitted bytes. This is a deterministic local heuristic, not billing or a guaranteed provider fit.

Publication's existing fresh read retains exact selection/cutoff checks, nonempty contiguous-prefix and complete tool/private-bundle validation in source order, exact derived protected-record and latest-fact checks, and direct suffix copying. Current/historical reads retain strict index/genesis source-metadata agreement, row policy and continuation semantics; no predecessor body is needed for current projection. Summarizer range labels retain component identity/kind, exact UTF-8 ranges, total bytes and `omitted_source_bytes=0`, not source hashes. Actual request admission/hash and the 16-call limit are unchanged.

The preferred recent-source tail target is `floor(I * tail_fraction)`, with default `tail_fraction: 0.25` and route usable input `I`. It counts all marker-defined agent-session rounds, including the newest open/inherited round—not individual provider calls or card lifecycles. When newest fits, compaction retains wholly fitting rounds backward and retains or covers the first older straddler whole according to `snap`; it never partially splits that older round. Only an oversized newest round uses a recent row suffix: retain the crossing row, stop at exact equality, then snap the covered prefix backward to an existing safe atomic boundary (or zero), under either snap setting. At zero target the desired suffix is empty. Atomic tool/private groups may retain more than the target or leave no positive preferred endpoint; the normal whole-round branch still requires its exact boundary to be safe, otherwise zero.

This is a source preference, not a final fit or retention guarantee. At most two distinct positive increasing endpoints—the preferred prefix and unchanged furthest safe fallback—feed one sequential accumulator and one successor genesis. Fallback can cover the entire settled tail even when the preferred source suffix fits its target. Preventive accepts preferred immediately only when strictly estimated-token shrinking, hard-ceiling-fitting and at/below trigger; otherwise it tries furthest and selects the smallest qualifying estimated-token projection. Authoritative recovery stops at its first token reduction; local exact admission chooses the smallest qualifying image-aware accounting-byte projection strictly below rejected, tying toward furthest. Descriptor-based measures include encoded image-part weight and raster reservation without loading pixels; text-only values are unchanged.
