# System Architecture

This document is the canonical architecture authority for Saivage v3. The current durable-format cutover is reset-only; old binaries, mixed formats, migrations, compatibility readers, bridges, and normalization paths are unsupported.

## Deployment And Trust Model

Saivage is designed for an externally isolated LXC container. Deployment provides that isolation as the boundary against agent-caused host impact; Saivage neither creates nor verifies it. In-container agents are trusted and may execute shell commands as root.

Internal path, command, and process controls serve operational and API-contract purposes, and runtime/data invariants preserve ordinary correctness and integrity; none contains that trusted root-capable principal. Ordinary workflows may remain constrained despite that capability. External operator authentication and outbound secret non-disclosure remain genuine product boundaries.

## Activation Ownership Architecture

The supervisor owns one `Map<string, CardActivationOwner>` and one guarded synchronous `ownershipTransition`. `CardActivationOwner` is plain activation-local state and the one `CardProcessActor` implementation is the remaining micro-actor, built over a narrow `BaseActor`. `ConversationLLMActor` is a separate direct provider/tool phase owner.

The direct Conversation LLM owner has no `BaseActor`, compiled topology, event queue, `start()`, or actor lifecycle settlement. The transition mutates only in-memory owner phases, parent/child links, currentness, run/token/status, readiness, the singular halt identity, exact-run Pause state, and the linked child lease, then validates the graph and emits one coherent invalidation. Persistence, process calls, abort delivery, promise delivery, and joins occur outside it and continuations recheck exact identity. Ordinary coordination has no owner repository, factory, registry, second ownership axis, transaction, recovery protocol, or callback bridge. The sole narrow callback exception is the required terminal CardProcess actor-main notification to its exact current/frozen Supervisor owner.

Each configured processor is directly constructed and started ready before its owner is observable. The supervisor constructs one `PlannerChildControlPort` bound to that exact parent activation and passes it through process/node/role composition. Provider code cannot select a parent or read an activation target before delegation. Concrete `CardService` remains the sole root/card reader.

`ConversationLLMActor.toolInvocationContext(outcome)` is the only production constructor of the complete invocation context for autonomous and Analyst calls. `invokeToolForLlm(surface,name,args,context,signal?)` is the singular LLM invocation boundary and has one required-context declaration; no overload, default, fallback, partial context, or role subtype exists. Analyst parses protocol arguments and passes the parsed object directly to that boundary. Lower-level `invokeTool` remains context-optional for direct non-LLM use. Analyst cannot activate children because its surface and dependencies contain no planner port. Valid Analyst and Invocation Service app-log ownership remains; autonomous runtime and Planner dependencies remain free of `appLogs`.

`AnalystSession` is a plain serial phase coordinator. Admission moves one pending restart-confirmation capability into one accepted operation, whose immutable accepted ID is distinct from every fresh initial, tool-continuation, and repair invocation source. Its tracker consumer alone installs reusable idle, permanent failed, or disposed settlement and delivers the caller. Reusable non-scheduling outcomes restore confirmation before delivery; successful schedule return alone consumes it. Confirmed restart separates one accepted-ID activation/user batch from schedule entry and fences both after the complete writer boundary and immediately before scheduling.

The direct Conversation LLM union carries each exact canonical input, provider lease, parked tool context, and concrete child lease in its owning phase. Direct replacement is the sole transition authority. Provider entry creates the invocation lease; canonical writer entry owns publication plus every synchronous observer. Completion then publishes mandatory provider-exchange evidence, synchronously hands the exact terminal input to the enclosing Analyst or Card operation, and settles the direct promise. Analyst outer settlement writes a required terminal-source notice only after an error/model-issue row and evidence. No queued terminal event, lifecycle join, registry, ledger, or mutable latest-input authority exists.

Cancellation before Analyst ingress writes activation/workspace/user plus an accepted-source notice atomically; after ingress but before nested ownership it writes only that accepted-source notice. Nested-first cancellation instead claims the exact current LLM input. Parked-tool cancellation writes its failed tool result and notice under the parked source. Ordinary `settling_tool` has one nested first-winner terminal request: the claimed result or entered callback completes once, cancellation appends only one exact-current-source notice, and later continuation/provider effects are suppressed. Entered provider/model-error completion retains `${terminalSource}:error`, mandatory evidence, handoff, required `${terminalSource}:message`, and delivery despite disposal. Only later optional runtime/UI/read-model projection is suppressible. Append, observer, evidence, or handoff failure is preserved unchanged and authorizes no retry, read, fallback, or compensation.

Only positively classified pure pre-effect Analyst preparation rejection is reusable; unclassified, observer, cleanup, and invariant rejection poisons admission, while publication uncertainty reaches fatal delivery before poisoning or cleanup. Disposal and shutdown snapshot exact operation, provider-lifecycle, and child-lease joins, start all joins, and propagate ordinary failure only after all settle. The supervisor's plain owner, `ownershipTransition`, parent-bound planner port, lease phases, and result winner remain singular. Exact result claim installs direct `continuation_closed` before record publication; an ordinary runtime halt may abandon that near-terminal result and fences every continuation from post-freeze mutation.

Run preparation installs `prepared_root` before recovery/running publication. Owners have only the result/cancel terminal winner; Stop, application close, and terminal actor-main invariant failure converge on one supervisor halt identity. Outcome-unknown publication instead reaches fatal delivery before halt installation. The actor callback verifies exact current authority or frozen-halt membership for ordinary actor-main failure. The ordinary halt freezes the owner graph, closes admission, settles promises, and aborts/disposes owners before joins. Successful quiescence clears process-local authority; interruption/join/termination failure retains the halt and graph. Runtime controls remain delegation-only and the supervisor remains the sole intervention-binding mutator.

The exact card stream format is v2. Persistence, operator schemas, and inferred web types share one strict complete `CardRecord`: nine required literal-null fields, two required nullable terminal status companions, named-agent or runtime creator identity, and exact lifecycle branches. There is no permissive transport overlay. `NewChildCardInput` contains only production child inputs and `CardEditPatch` only title, tags, priority, urgency, and related. Agent edit is admitted only from backlog/changed/stopped; blocked and failed are first reopened to changed. Dedicated notification, lifecycle, child-link, reorder, and deletion methods construct their exact candidates and history metadata directly.

Identity derives structural parent/depth but never membership. Disposable `CardIndex` projections follow each reached parent's committed `children` array and filter it to active records. Operator and tool convenience fields are separately named explicit projections. `CanonicalCardFilesReadModel`, through CardService's canonical projections and descriptor-backed snapshot, is the sole `.saivage/cards/**` Files path: it returns exact v2 bytes and propagates strict v1/old-shape failure without generic filesystem fallback. Full-chain recovery remains leaf-to-root with valid partial prefixes, but v2 replay recognizes lifecycle-only stopped transitions.

The supported runtime is Node.js 24 with npm `>=10 <12`, matching `package.json` engines and CI.

## 1. Ownership Model

The runtime is card-centered and alone dispatches work. Startup structurally compiles the complete named-agent catalog and one independent workflow per card type, then binds that immutable artifact once to live dependencies before any actor starts. A card selects only by its immutable type; there is no family or role dispatch and no runtime config lookup or merge.

`compileProjectWorkflows` is the sole deterministic local structural stage. It exact-reads and freezes the selected card-specific/generic/bundled agent templates and every referenced process prompt, closes the nine graphs, records, bootstrap definitions, local terminal exports, latest-node existence/path, child sets, and model-route syntax, and performs no provider, credential, MCP, process, or network work. `init`, `reset`, ordinary start, and `start --create-runtime` all receive that singular result before generated-state publication or deletion. `bindRuntimeWorkflows` is the startup-only second stage: it resolves and freezes each named agent's capability-compatible concrete provider candidate chain after concrete Registry construction. Server composition passes only the bound artifact to runtime actors; reconfigure's candidate compile is validation-only and is never installed.

All node-to-node and terminal edges share one acceptance owner. `AgentNodeExecution` prepares every required closed/open projection before mutation, terminal routes claim the existing winner before close, and updated streams close once in requirement order. The returned immutable close projections are the only source for accepted URLs, transition context, and terminal exports. `CardProcessActor` retains the latest accepted result per node only in activation memory and applies `current` or graph-reachable `latest_node` promotion at the terminal route. A primitive-classified `PublicationOutcomeUnknownError` from a close reaches fatal delivery before result acceptance, Supervisor halt, lifecycle publication, or parent settlement. Ordinary pre-commit close errors remain ordinary node failures.

One plain `CardActivationOwner` holds each mapped activation in exactly `prepared_root | child_admission | active | settling`. The sole `CardProcessActor` directly extends the narrow `BaseActor` and owns configured process position, activation tracking, exhaustive guarded activation settlement, LLM ownership, node transitions, and local join. BaseActor's generic one-shot terminal hook rejects current/future lifecycle waits with the exact latched error and forbids pump restart. `AgentNodeExecution` owns one node's compiled named-agent surface, prompt, correction, record, notification, and cleanup behavior. The supervisor's one map, terminal winner, and nullable halt record are the sole publication, cancellation, currentness, and freeze authority. Durable running without an exact owner fails fast.

Supervisor pre-admission and project-root preparation are the only root activation boundary. Startup uses required concrete `actorStore`; there is no second root reader. Root ownership is installed before recovery or running publication. Child activation exists only through the exact parent-bound port and invocation lease. Every processor is started ready before owner visibility and activated only after successful running publication.

Cancellation claims the exact active suffix synchronously, preserves already-done descendants, aborts only under cancellation authority, publishes deepest-first, and joins one cached owner settlement. Natural release removes the exact owner/relationship from the one map before caller delivery. This is process-lifecycle authority, not a persistence lock, queue, transaction, generation, or currentness mechanism.

Card status behavior is intentionally operation-named rather than one terminal taxonomy. The cards-owned `card-status.ts` implementation exports exactly four small predicates/effects, and `status-api.ts` is their singular cross-package entrypoint: `canCreateChildInStatus` admits backlog, changed, running, blocked, and stopped; `canCancelCardStatus` admits every status except done and cancelled; `acceptsCardNotifications` admits backlog, changed, running, blocked, and stopped; and `analystBriefEditEffect` preserves backlog/running/stopped, reopens blocked/done/failed, and rejects changed/cancelled. Role, root, runtime, type, dependency, and publication gates remain at their owning surfaces. In particular, Analyst create additionally rejects running, while blocked remains unresolved and parent-planner-re-enterable.

Status-to-process admission has one nullable mapper: backlog maps to BACKLOG, changed to CHANGED, blocked to BLOCKED, stopped to STOPPED, and running/done/failed/cancelled to null. It grants no transition authority. The supervisor invokes it only after exact owner absence and one admission read; rejection precedes owner/processor construction. Stopped uses dedicated `activateStopped()` publication.

Each card-type topology compiles once into immutable states, transitions, named node contracts, child sets, record definitions, exports, and promotion. `CardProcessActor` executes that artifact one node at a time and retains accepted result-by-node memory only for the activation. The narrow `BaseActor` owns state-transition mechanics plus its generic terminal-failure latch/hook. Same-node reentry clears the settled task before entering the new node. CardProcess joins every frozen lane and chooses failure in fixed order: pre-join cleanup, LLM actor order, tracker, then lifecycle. App-log publication failure sends no event and makes Supervisor start the singular runtime halt; actor-main failure reaches the same halt through the narrow exact-owner callback while remaining a distinct failure policy.

Every accepted edge uses one record-acceptance algorithm before transition. It freezes requirements, closes every required open record sequentially in declaration order, and records only close-return URLs. Only after all closes succeed does it accept the node result and transition; terminal edges also choose ordered exports and promotion. Primitive-classified close uncertainty permits no later close, read, retry, transition, correction, fabricated result, lifecycle publication, parent settlement, or Supervisor halt; fatal delivery exits. Earlier successful closes remain durable but the node is not accepted. Ordinary pre-commit close errors remain ordinary node failures.

Other status decisions remain exact and local: running-chain membership is `status === 'running'`; dependency completion is `status === 'done'`; descendant completion is done-or-cancelled; activation settlement is done/failed/blocked with a distinct cancellation branch; deletion and Analyst reorder reject running; immediate-parent edit preserves backlog/changed/stopped, reopens blocked/failed, and rejects running/done/cancelled; and projected start admits only backlog/changed/stopped. Planner reorder is deliberately different from Analyst reorder: it may reorder the current running planner parent's children, whereas Analyst reorder rejects a running parent or running member of a requested child subtree.

## 2. Card Identity And Discovery

Card identity is `project` or one-to-five lowercase alphabetic hierarchical segments selected from a deterministic parent-local spreadsheet sequence. Every create starts at `a`; exact candidate namespace creation claims the segment, and only candidate `mkdir` `EEXIST` advances to the next segment. Collision handling never lists siblings or inspects the candidate. Parent, depth, namespace, exact card/record streams, and named-agent conversation paths are forward-derived. `CardRecord` has no `position`. Backend `listChildren`, logical-path, reorder behavior, and web nested/direct-child projections follow each reached parent's committed cumulative `children` array order; active projections omit retained tombstoned links without changing that order.

One non-root attempt exact-reads and validates its linked parent and existing dependencies, then exclusively claims `.saivage/cards/project/children/<s1>/.../children/<sn>/` for the first candidate whose direct `mkdir` succeeds. `publishInitialChildCard()` constructs the complete card and brief from exact child input; `publishInitialProjectCard()` separately constructs the complete root from only title and brief. Dependency state is immutable after version 1. Existing-card-only dependency creation is cycle-free by construction, so mutation-era service/index cycle preflight does not exist; `validator.ts` alone retains whole-loaded-graph dependency-cycle rejection. The later parent append alone grants linked membership. A failed claimed namespace remains consumed and ignored.

Successful-path visibility begins only after the confirmed parent-link append. Readable initial child streams before that link are not membership. An append or replacement error is outcome-unknown and authorizes no read, probe, retry, reconciliation, or artifact inspection. Card-only readers derive the bounded linked chain and validate each reached exact `card.jsonl` once. Complete initial publication separately proves the card type's configured bootstrap record; an explicit authored-record resource derives and validates only the exact requested configured stream. A terminal tombstone makes that card absent and terminates descendant traversal. Direct exact-known conversation I/O remains lifecycle-ungated. Namespace-only, bootstrap-only, temporary, unlinked malformed, and arbitrary noncanonical entries are silent ignored orphans.

## 3. Direct File Persistence

Saivage-owned persistence is direct stateless synchronous file I/O by the domain or actor owner:

- `card-files.ts` owns direct deterministic child-namespace claiming, complete initial stream publication/proof, exact `card.jsonl` reads, append-only card versions/history, cumulative child links, and terminal tombstone rows.
- `authored-record-files.ts` owns direct append-only streams selected by explicit compiled `RecordDefinition`. Version-2 rows carry exact record name, schema, format, and named writer. The workflow bootstrap record alone receives a closed initial row from `runtime:bootstrap`; every other configured stream may be absent. No registry, slot enum, sibling scan, or brief-specific first-row branch exists.
- `conversation-file.ts` owns one stable append-only conversation per deterministic named-agent session.
- `contracts/app-log.ts` owns the strict three-lane `{type,data}` union for event, control-action, and provider-exchange rows. `persistence/app-log.ts` owns the sole direct synchronous preparation/validation/serialization/append boundary and strict reads, using the current project root directly. Domain producers supply preparation closures and invoke their narrow direct post-commit effects only after successful publication.
- `provider-exchange-log.ts` is the singular latest-provider-exchange selection owner. Each invocation strictly acquires the complete provider-exchange lane once and reduces it once by exact session ID, greatest timestamp, then greatest attempt index, retaining the earlier physical row on an exact tie. Singular exact lookup delegates to that same map implementation; no second filter/sort comparator exists.
- `ResolvedConfigAuthority` owns selected YAML document reads, effective validation, and config mutation orchestration; `config-file.ts` owns canonical atomic replacement.
- `auth-profile-file.ts` and `project-identity.ts` own their single canonical files.
- `runtime/lock.ts` is the exceptional process-exclusion boundary only.

One strict `cardRecordSchema` defines every current `CardRecord`, including card-version, embedded history-snapshot, and tombstone-final fields. The card-stream row schema is the sole structural parser for each raw row at read and write boundaries; `validateCardStream()` consumes only those typed parsed rows and performs identity, history, transition, immutable-field, child-link/reorder, ordering, and tombstone validation without another Zod parse.

The current singular operation grammar has no common patch writer, caller-selected context, optional terminal companion, generic dependency mutation, or broad transition API. `commitActivationOutcome()` is the sole running-to-done/failed/blocked publisher and derives lifecycle, both required status companions, and notification clearing from the non-cancelled outcome and one settlement timestamp. Generic status owns only backlog/blocked/changed-to-running, blocked/done/failed-to-changed, and the six admitted cancellation sources; recovery and stopped activation own their disjoint pairs. Every actual delta has deterministic order and recomputed summary. The eight discriminated history families carry fixed row-local provenance. Replay scans no child stream and proves only row-local facts: notably child-link is runtime-owned, while reorder replay proves the private complete same-membership full-order primitive, not the public operation's historical active-set admission.

The bottom-layer card schema keeps its notification-format invariant locally and imports no card behavior: complete done, failed, and cancelled records require empty `pending_notifications`, while backlog, changed, running, blocked, and stopped may retain them. This exact schema refinement intentionally duplicates the higher-layer notification predicate rather than creating a `schemas -> cards` dependency.

Planner child admission exact-reads the linked target and each dependency in declared order. It never invokes list/tree/index APIs and retains no authorization state. Linked-tree operations start at the exact root and recursively follow committed `children`; their disposable projection validates active dependencies and hierarchy and is discarded with the call. Multi-root deletion uses that one fresh projection to form a subtree union, reject permissions and surviving dependents, and topologically order dependent-before-dependency plus child-before-parent tombstones. This graph is call-local write admission, not persistence coordination.

The complete, duplicate-free cumulative parent `children` snapshot is the sole linked-membership and semantic-order authority, including retained tombstone links. A real active reorder uses one fresh operation-local parent/active-child projection, requires a duplicate-free permutation of the active IDs, and constructs one next parent snapshot with requested active IDs first and all retained non-active links afterward in stable prior order. It appends one parent version and never writes child streams. An active-order no-op has no append or effect, even when retained links are interspersed in the old complete order. Parent-local stream validation admits only a changed, same-length, same-membership permutation declared as a children-only reorder, with no other local field change; identity order, membership change, and piggyback mutation fail. Validation compares consecutive parent snapshots only and carries or derives no active/tombstone classification in history. Thus both the old and new complete parent rows are valid committed prefixes without reorder coordination.

Planner activation validates schema and immediate-child identity, reserves the exact invocation lease, and delegates through the bound parent port. The supervisor validates parent and lease before I/O; owner absence alone authorizes one admission/dependency/status read. It constructs and starts a ready processor, silently installs owner/relationship/lease, performs one running publication, then transfers currentness and activates the processor. Exact same-lease joins perform no I/O.

Dependency and non-activatable-status rejection precede owner and processor construction. They cause no running publication, relationship/currentness change, or execution work and add no scheduler, traversal, propagation, or cancellation behavior.

Every replacement and first JSONL publication calls `replaceFile`. It creates one fresh random UUID same-directory temp exactly once with `O_CREAT | O_EXCL | O_WRONLY`, writes and fsyncs it, renames over the target, and fsyncs the parent. A temporary-path collision or other failure propagates. Crash-left temps remain ignored forever. Publication-temp UUID generation and invocation UUID generation are distinct identity scopes; card identity instead comes from direct parent-local deterministic namespace claims.

All file, directory, append, and lifecycle-lock creation uses ordinary Node defaults filtered only by the process umask. No mode argument, chmod/fchmod, permission probe, or repair exists.

Growing canonical JSONL files use one result-bearing `appendEnvelope()` API: `appended` means write, fsync, and close all succeeded, while `missing` means only that the initial exact-path open returned `ENOENT` before a descriptor existed. Every caller handles both results explicitly. First publication separately calls `lstat` on the exact target exactly once: any successful result is ignored and means already published, only `ENOENT` permits one unchanged replacement attempt, and every other error propagates. It never opens or classifies an existing target, so files, directories, symlinks, FIFOs, sockets, and devices take the same present branch. App log alone may use append `missing` for one first-publication attempt; card, record, and nonempty conversation owners fail fast because their previously read append target must still exist.

Append acquisition uses `O_WRONLY | O_APPEND | O_NOFOLLOW | O_NONBLOCK` and descriptor metadata, never a path probe. The descriptor must be a regular file before any write. Every successful open has exactly one close attempt: an earlier stat/validation/write/zero-progress/fsync error takes precedence over close error, while a lone close error propagates, and close is never retried. The app-log writer validates and serializes only its incoming row and does not read existing bytes. Reader-local semantic indexes, global duplicate checks, and identifiable unterminated-suffix canonicalization remain strict full-read concerns and never authorize or prepare a write. Complete malformed data remains and fails; direct append never truncates an existing suffix.

The behavior-preserving growing-file read groundwork has two descriptor phases. A bounded byte-classification pass reaches EOF without decoding, identifies the last newline, and, when needed, truncates and fsyncs before any strict UTF-8/envelope work. Failure of either publication syscall raises the one shared `PublicationOutcomeUnknownError` and intentionally abandons the descriptor with no close, callback, inspection, or other follow-up. Ordinary stat/read/parse/reducer/replay failures close once with the original failure authoritative; successful truncation/fsync resumes that ordinary phase, and a lone final close failure remains ordinary. The second bounded positional pass frames one envelope at a time and gives reducers `{lineStart,lineEnd,rowOrdinal}` checkpoints. Replays reopen no path and pass each referenced complete envelope through the same strict decoder/schema parser. A separate metadata primitive reads exactly through the first newline and parses every row in that one envelope without opening or validating later history.

The inferred strict `LoggedEvent` union and runtime event schema agree on exactly `runtime_diagnostic`, `runtime_actionable_error`, and `mcp_tool_invocation`. The actionable-error envelope is strict. Error events are both runtime kinds and only failed MCP invocations; there is no generic routing metadata, replay-only event kind, content-review lane, or dedicated error lane.

Provider-exchange publication belongs to its agent producer, not generic app-log persistence or the provider-exchange schema. Immediately before strict parse and append, its typed projector preserves contract/provider/model/account, session/source/output, transport, attempt, status, time, response, finish, token, and terminal-tool identities. A direct `generic | codex | openai-responses` request switch copies only each adapter's known members; the HTTP(S) endpoint keeps scheme/host/port/path while removing userinfo/query/fragment disclosure, and only error message is prose. Logged-event and control-action producers likewise apply their discriminated projector before append and readers reuse it: actionable `contract_response_violation` and `invalid_enum_value` state have direct variants, while event/action/actor/target/surface identities remain exact. Schemas validate these projected singular contracts but never sanitize canonical bytes, and `app-log.ts` selects no redaction behavior.

There is no app-log dependency forwarded through Supervisor, `CardActivationOwner`, `CardProcessActor`, or `AgentNodeExecution`. Planner reorder and notification use canonical card/runtime evidence and append no control action. Analyst mutation settlement and Invocation Service retain their independent valid app-log ownership. Historical Planner control-action rows remain readable; current event discriminators and strict replay behavior are unchanged.

`appendAppLogEntry(projectRoot, entryType, prepareEntry, context?)` prepares identity/time, centralized redaction or projection, schema validation, serialization, and directory ownership before calling the direct growing-file primitive. Those failures remain ordinary. Only primitive-classified canonical uncertainty is `PublicationOutcomeUnknownError`; every reachable catch preserves it for immediate fatal delivery before retry, fallback, ToolResult/model/card conversion, later attempt, write, SyncHub hint, or volatile containment.

Terminal propagation follows the current ownership graph: direct `ConversationLLMActor` into plain `AnalystSession` or `CardProcessActor`, then the Supervisor's centralized owner/lease graph. CardProcess halts its failed task state without joining its own activation-tracker consumer. On rejection, Supervisor first installs the halt, terminally interrupts every admitted/settling child lease and owner settlement, then starts all processor joins. This settlement-before-join order breaks the Conversation LLM → child lease → activation dependency and prevents deadlock. Dynamic execution uses existing direct scopes under the runtime-card, operator-session, and service-infrastructure process roots; halt cleanup closes/joins only owned volatile scopes and cannot replace the publication error at its owning boundary. Exact continuation fences compare map owner, activation identity, relationships, and absence of halt before and after every await that could publish, activate, settle, or release. The exact consuming roots remain the global Fastify error handler, registered Analyst WebSocket message rejection observer, and Supervisor `activateProcessor()` rejection callback. They expose no cause and publish no replacement evidence.

`EventQueryService` is the sole event/error query authority. Each query performs one complete strict event-lane read and then filters/slices. `/api/events` supplies strict oldest-page or newest-tail selection with maximum 1000 and no session/since filters; `/api/debug/errors` is its complete derived error projection. `/api/debug/timeline`, ErrorLog, and duplicate event read models do not exist.

The strict global agent catalog is the sole agent authority. Each safe agent name selects one prompt reference, exact ordered tools, one named model route, skill capability, session scope, and child-creation ceiling. Skill index `target_agents` values are exact configured names; model temperature and token limits belong to named routes. No behavior is attached to the default strings `planner`, `reviewer`, `executor`, or `analyst`.

## 4. Card-Process Compilation And Execution

Startup strictly parses all nine `card_types` entries and structurally compiles one independent immutable topology per card type before actor construction. States are `lifecycle:ready`, `entry:<port>`, `node:<id>`, and `terminal:<port>`; accepted outcomes are `result:<outcome>`, while `execution:failed` is runtime-owned. Nodes reference card-scoped named agents and contain their exact contextual record and child authorities. Entries are exactly `BACKLOG | CHANGED | BLOCKED | STOPPED`; terminal ports are `DONE | FAILED | BLOCKED`. Every node is entry-reachable and has a terminal path. Terminal exports must be source-node requirements, and `latest_node` promotion must name a node with a directed path to that terminal source.

Process prompts use exact `src/prompts/<card-type>/process/<identity>.md` defaults with `.saivage/config/prompts/<card-type>/process/<identity>.md` overrides. Agent templates select card-specific `.saivage/config/prompts/<card-type>/agents/<agent-name>.md`, then generic `.saivage/config/prompts/agents/<agent-name>.md`, then bundled `src/prompts/agents/<prompt-ref>.md`; only exact `ENOENT` advances fallback. Startup loads referenced prompt content, requires exactly one `{{contractDescription}}` for workflow agents, rejects obsolete fixed-result directives, and renders every configured card-type/agent/node pair.

`CardActivationOwner` retains the selected lifecycle entry and ready parked `CardProcessActor`. Direct state-entry and transition hooks execute the card type's startup-compiled definition. Entry queues its configured route without I/O; node entry starts the sole task; transitions invalidate runtime projection. If any transition, entry, task-result callback, or framework invariant escapes, BaseActor terminally latches and reports it; CardProcess rejects its unsettled activation before synchronously notifying the exact Supervisor owner. The first node ordinal is 0 and accepted node reentry advances it once. `AgentNodeExecution` consumes the compiled agent, prompt, tool, record, descendant-context, model, and outcome contract without role or family lookup.

`buildAgentSurface` composes provider implementations, then selects exactly the configured agent's ordered tool names and rejects duplicates or missing definitions. Child and record operations receive the node's precompiled contextual sets; global Analyst record mutation instead resolves the target card's compiled definition. `mcp_tool_call` is ordinary global tool admission and has no annotation- or agent-name branch. `AgentNodeExecution` directly creates the strict node-result schema and appends its sole `emit_result` definition after the operational array. A terminal call first passes the direct non-null, non-array object guard and then strict schema validation; either failure is appended through the same-node correction loop. Beside this owner, one strict `EmitResultSettlement` parser admits only accepted `{accepted:true}`, a nonempty-error failure without data, or the exact pending-notification reason. Every direct malformed-argument, notification, record, stale-context, incomplete-descendant, and accepted branch parses its value immediately before the existing append or settlement. The `emit_result` outcome selects a compiled edge and is distinct from the compiled `DONE | BLOCKED | FAILED` terminal ports; this boundary does not alter record closure, acceptance, fatal-publication escape, continuation, or cleanup order.

`SkillCatalog` is the narrow stateless boundary for the exact optional `.saivage/skills/index.json` and selected skill files. On each explicit call it validates the complete strict current index, filters by the supplied configured agent name, preserves operator order, and projects names or reads one exact authorized file. Only exact index `ENOENT` means an empty catalog; malformed present data and selected-file failures propagate. `createSkillProvider` is installed only when that compiled agent declares both `skills: true` and the `skill` tool. `mcp_tool_call` remains separately and singularly owned by `mcp-provider.ts`.

The tool-result persistence boundary retains the provider's complete invocation envelope unchanged. For skill success this is exactly `{success:true,data:{skills:[{name}]}}` or `{success:true,data:{skill_name,skill_content}}`; failure remains the generic `{success:false,error}` envelope. `tool-friendly.ts` passes that serialized complete result through the public presenter registry. The registered skill success presenter reads only the complete envelope's `data`: lists render `N skill`/`N skills`, including zero, and named loads render `skill loaded`. The registry classifies failed envelopes through its generic error path before any skill success presenter; there is no bare-payload compatibility projection or skill-specific error path.

One LLM options path carries the supplied ordered tool list to every provider transport. A non-empty list is sent with only `tool_choice: 'auto'` and `parallel_tool_calls: false`; an empty list omits the tool fields. There is no forced-name choice or provider terminal-phase path. These generated roots are removed as whole trees without descendant inspection. Durable configuration and operator inputs under `.saivage`, including identity, credentials, prompt overrides, skills, and instructions, remain outside that ownership boundary, as do source and canonical documents.

The `.saivage/locks` namespace is the exceptional lifecycle-exclusion boundary, not reset-owned generated persistence. Reset acquires the exact canonical `runtime.lock`, removes the four complete roots, publishes the new `project` root card while still holding the lock, and then uses exact-owner release. A pre-existing exact lock blocks deletion. Lock siblings and every other outside-boundary path are neither discovered nor cleaned. Mixed-version operation and rollback against current-format state are unsupported.

Saivage file persistence does not guarantee no data loss. Interrupted external effects may repeat; notification context may duplicate; concurrent auth refresh may overwrite another change; incomplete card namespaces and publication temps may remain forever. Exact canonical corruption fails clearly for operator repair or reset rather than automatic recovery.

## Universal publication fatal delivery

`PublicationOutcomeUnknownError` is the dependency-neutral signal from direct file
owners, and `ApplicationFatalPort` is injected from application composition. The port
uses synchronous fd-2 output followed unconditionally by `process.exit(1)`. Catch
guards rethrow the same instance until the earliest concrete owner can deliver it.
`BaseActor` stays persistence-neutral through a no-op fatal-task hook; its sole
production subclass, `CardProcessActor`, supplies fatal delivery. `ConversationLLMActor`
is a direct phase owner, while `AnalystSession` and `SupervisorRuntimeApi` remain plain
coordinators. `AnalystWsHandler` owns both turn and queue rejection boundaries.

Replacement uses exclusive same-directory temporary publication and becomes uncertain
at rename. Growing-file and bounded card-record readers become uncertain at truncation.
Lifecycle-lock first creation syncs its parent directory and treats the created empty
namespace as known. JSONL append uses `missing` only for exact append-open `ENOENT`;
process output requires its prepublished exact file and leaves every open error direct.
All canonical write loops permit only proven-zero-transfer first-write `EINTR` and
suffix-only completion after short writes.

Process logs use no `WriteStream`, pipe, retained descriptor, or writer lifecycle.
Each data callback performs one synchronous exact-file append. Presentation settlement
joins managed-group absence with both captured readable drains, and all three
ProcessRunner termination surfaces join only report `stopped` identities before
returning. Reader-local projections remain disposable; recovery writes remain
append-only and do not create indexes, body rewrites, or recovery coordination.
