# System architecture

Initial root publication prepares the exact card directories and all configured
root-session indexes, then the global Analyst index, before selecting the root
head. Oversight stays lazy. The final initial-card publisher does not create or
adopt directories; child creation likewise prepares its exact namespace before
publishing records/artifact/head. Direct CLI mutation composition awaits its
callback under lifecycle exclusion; publication uncertainty retains the lock even
when a test fatal boundary throws.

The native-hybrid evidence contract distinguishes real activation
ownership from root-only bootstrap commissioning. Init/reset own one managed process
registry/runner and a lifecycle-scoped container; signals cancel that initializer
without releasing exclusion. Ordinary release follows callback and process
settlement. Startup creates its one application registry before bootstrap and
passes that same registry/runner into server services and Supervisor. During startup
signals abort initialization, not a terminal cleanup that would join itself.

Fresh bootstrap qualifies clean explicit delivery D and absence of the exact
private ref before generated namespaces. After configured root sessions and Analyst
exist, the managed `commission` step reconsumes D/absence, creates only that ref,
and verifies unchanged checkout/source. Its truthful bootstrap finish precedes
authored records, initial card artifact and selecting head with completed source
facts/policy digest. Strict generated-state admission follows. Retained roots must
match ON/OFF and exact compiled source policy; they never replay commissioning.
Reset preflights clean delivery and unused provisioning before any generated-root
deletion. The provision-required classic-git bundle now compiles and materializes
through public init; [validation](../validation.md) records functional constituent
qualification and known aggregate/security limits.
Structural bootstrap tests alone are not CLI rollout or first-Run evidence.

## Native Git dependent implementation boundary

Card6 gives CardService a strict runtime-only source-fact publication path.
Ordinary/tombstone payloads require nullable root/child `git` facts, with immutable
root policy/branch ownership and retained original correction provenance. New
OFF bootstrap, child and repair cards initialize null; commissioned ON root
publication selects completed source facts. Safe read models project detached
source refs/OIDs and redact ref text; no source bytes, approval or helper phase is
stored there. Supervisor owns runtime source sequencing and activation frontiers;
held or mismatched source blocks further execution.

Workflow5 adds the correction participant to the existing compiled state table,
not another engine. Structural declaration compilation selects actual task/feedback
prompts and named agent sessions; runtime compilation and binding enforce ON eligibility.
Generated native transitions distinguish entry, verified saved-entry return and
blocked/failed reporting from authored product edges. Node purpose is explicit in
the compiled contract and graph projections, never inferred from historical text.
The actor excludes correction from product accepted-result promotion; urgent
continuation waits for source settlement and refuses continuation on held source.

Eligible ON workflows use Supervisor/CardService integration. In-process GitWorkflow's
failed-rebase preservation uses two separate invocations: capture final eligible
source leaves without changing the real index, then (only after the owning caller
successfully publishes the snapshot) normalize the real index, abort once, restore
the snapshot and checkpoint/return. Original replay history and current source
selection remain distinct. No saved phase authorizes restart or adoption.

Every Git argv runs directly in its own existing ProcessRunner-managed group.
The coordinator awaits the saved whole-group/capture settlement and reconsumes
current owner authority before continuing. An exited-zero leader with a killed
descendant is containment, never command success. Finite naturally exiting hook
children remain supported; their effects are consumed at the next source check.
The runner owns exact optional binary/NUL stdin and rejects incomplete/broken input.
Publication uncertainty crosses the fatal boundary before cleanup or another read.

Capture treats directories as containers, not retained leaves. Exact native-start
and current-index membership retain now-ignored tracked source; unrelated ignored
data is not captured. Before destructive transitions, only threatened selected
prefixes are checked for uncaptured obstructions. After index-writing hooks settle,
final observations compare bytes, modes, links and index entries without refresh
or index writes, then proceed directly to abort or restore. A hook-created ignored
obstruction means known normalization but held source, not successful return.
Real-index conflict stages may be lost after snapshot selection even when return
later fails. Native-domain qualification alone does not establish complete actor
integration, product acceptance, UI or full native-hook qualification.

The Supervisor's native foundation now enters commissioned root/child source
before provider admission, joins the parked parent's command writers and publishes
its checkpoint before child entry, and returns failed/cancelled/interrupted source
before terminal publication or child-lease delivery. A Supervisor-owned source
task outlives cancellation of the failed agent, but is aborted and joined by the
existing runtime halt. Parent command scopes remain usable after child return;
only their exact node-owned processes are settled at handoff. Snapshot publication
and its N/Q continuation remain within that same live source owner, not restart state.
Urgent source failure requests halt without awaiting the halt that joins the urgent
task, and reports queued/suppressed rather than a successor. Whole-workflow ON
remains rejected until commissioning and bundle
integration are complete; successful product settlement is not
substituted with an unreviewed source return.

NodeExecution carries the prepared source tuple and node ordinal only in the
same-activation AcceptedNodeResult map. Preparation precedes handoff, record close
and successful emit_result; every await reconsumes current owner/node control and
the applicable record, descendant, review and notification gates. Joining actual
writers leaves the node scope available for ordinary corrective rearm. Reviewer
entry prepares before snapshot/provider admission; approved review verifies that
exact clean selection. Root reviewed completion verifies the promoted tuple without
preparing later source, while retaining assessment exports separately from review
authorship/summary. No approval is serialized into card Git facts.

The processor passes its terminal promoted tuple to Supervisor settlement.
Supervisor joins the processor and delivers on the real parent index, verifies
files/index/refs and publishes parent then child facts before terminal outcome or
lease release. A no-change squash leaves the parent commit unchanged. Later dirt
refuses rather than checkpointing under old approval. Git effects and the two
fact publications are not transactional; a failure leaves a stopped mismatch,
not a retry or automatic return path.

Global workspace mutation and delayed Webfetch save contexts carry the Supervisor's
final source-file admission callback through internal and external Analyst
composition. ON construction requires it. File owners resolve the destination or
its existing ancestor and invoke it synchronously before any mkdir/read-for-edit/
write; multi-file patches classify all destinations before effects. The gate uses
existing status, run identity, prepared launch, active owners and halt/transition
state, plus strict root facts and read-only Git inspection of exact delivery.
Starting ownership is reserved before the first asynchronous entry operation.
There is no whole-Analyst-turn join, source lease or cached admission.

Synchronous Git queries share a finite five-second remaining deadline, disable
optional locks and lazy fetching, and never use status, diff/textconv, refresh,
filters or index/object writes. Unsupported fsmonitor/transform/sparse state
refuses. Real index entries are compared with the selected tree, and actual file
bytes, executable modes and symlink bytes are compared directly with blob hashes.
Missing local objects refuse rather than fetching. Normal mutating Git continues
only through the existing asynchronous managed-command owner.

Frozen ON global capability validation checks canonical provider identity at
declaration and binding. Unknown command-backed/quality/MCP writers cannot be
selected; observation and process containment are unchanged. MCP composition
receives the frozen mode and refuses dynamic capability enlargement at the owning
manager, including HTTP lifecycle calls and persisted reconciliation. Config setters
still validate their complete candidate and require restart; they cannot replace
the current bound surface or weaken the manager's frozen mode.

The compiled correction Executor now runs in its ordinary configured card session
and state table. Native verification joins its command writers without closing the
scope needed for corrective feedback. A refused `source_ready` follows the ordinary
result-correction route; successful verification publishes the actual rewritten tip
before the node returns to its saved entry. Correction results never populate the
product accepted-result map. If correction blocks after a completed rewrite, the
owner verifies/publishes the new tip while retaining the original task and snapshot
provenance for explicit reentry. Snapshot return keeps original C, current O,
native N and detached Q distinct across repeated interruptions. Surviving urgent
correction joins only its retiring node, preserves/returns/reenters source, then
releases the guarded correction successor before ordinary STOPPED continuation.
An entry refusal can publish runtime-owned Git BLOCKED only when the native owner
established the clean exact parent and performed no mutation. Partial transfer or
unqualified source remains held; no provider or compensating checkout is admitted.

Quality tool binders depend on the contract-layer `QualityToolPort`, not runtime
implementation. Runtime/application composition binds the selected agent's frozen
configuration and actual owner process scope to `executeFiniteOperation`, using the
same compiled definitions as actions. The external Analyst surface uses the configured
Analyst policy, independent of credential attribution. It supplies no card binding,
execution-log observer or record publisher. Shared cleanup completes before private
report bytes become a tool result. Outbound configuration excludes provisioning.

## Observed source query ownership

`contracts/observed-collections.ts` declares the backend-neutral two-operation
`RetrievalPort`. Runtime composition loads strict logical/private inputs once and
passes one query owner through Supervisor/card execution and both Analyst surfaces.
Tool binding uses the existing observational result policy and caller VFS reader;
custom configured ceilings still decide which operations exist. Oversight remains
unchanged. The private transport is never exposed through show_config or results.

`retrieval/xerj-retrieval.ts` owns authenticated loopback HTTP, redirect refusal,
bounded bodies and request-local catalog/mapping/search projections. Dataset
`run_id` joins native run metadata to the exact adopted root and prefix before
selection; a prefix or guessed destination alone is insufficient. Known native
text carriers (`body`, `impl`, `text`, plus lexical `name`/`title`) and actual
inferred semantic mappings select channels, not a
remembered inventory or universal embedding promise. `observed-collections.ts`
owns logical filtering, ordinary-reader admission, same-content alias projection,
redaction-before-caps and ordinal reciprocal-rank fusion (constant60; weights1:1,
1:2 or2:1). No original-source body reread or independent content mirror is added.
Excerpts select string `impl` then `body` then `text`; arbitrary inferred columns
are withheld. Native line-window `text` can join/cap lines, so coordinates remain
unavailable. Availability is aggregated across destinations; successful metadata
never hides another destination's `metadata_unavailable` limitation, and failed
metadata never overwrites available evidence. Metadata loss keeps coverage unknown.

The offline prepare owner emits engine/watch argv and systemd units. Deployment
alone owns native lifetime, credentials, assets and automatic observation. App
Stop/close and query cancellation do not stop it. No ingestion API, index/mapping
provisioner, custom watcher, capability registry or periodic rebuild exists.
Native persistence is external derived tool state; Saivage adds only the two
strict operator input families recorded in the durable format reference.

Saivage supports autonomous software development through a card-centered runtime:
configured Planner, Executor and Reviewer nodes separate coordination, engineering
and assessment. Configuration compiles the workflow, Supervisor
owns dispatch and activation lifetimes, domain owners publish ordinary files, and
read models expose selected evidence. The browser observes those owners; it is not
a scheduler or persistence authority. This is the canonical architecture
explanation. [System requirements](../spec/system-specification.md),
[exact UI contracts](../spec/operator-ui-contracts.md) and
[operating procedures](../runbook/index.md) have separate owners.

## Ownership and dependency direction

| Owner | Owns | Does not own |
| --- | --- | --- |
| `schemas`, `contracts` | Strict identities/data, pure validation, operation-indexed transport and execution contracts | Filesystem, provider execution, scheduling or application lifecycles. |
| `config` | Selected YAML/effective input, registered init templates and structural candidate validation | Live replacement of installed workflows or compatibility detection. |
| `cards` / direct persistence owners | Current linked cards, named record mutations, exact selectors/history and file publication | Dispatch, generic stores, transactions or orphan adoption. |
| `runtime` | Compile/bind, Supervisor, CardProcess, NodeExecution, conversation phases, context/compaction | Provider transport implementation or an independent durable runtime-state file. |
| `agents` | Registry/Router, request plans, protocol adapters, attempts, credentials and exchange projection | Card dispatch or runtime actor topology. |
| `tools`, `workspace`, `mcp` | Scoped invocation, resource admission, transport/discovery and owned effects | Inferred role authority, remote restart guarantees or historical replay. |
| `application` | Composition ports, Analyst operation surface, read models, mutations, Oversight schedule and freshness effects | Generic repository/store lifecycle or a second Supervisor. |
| `server`, `boot`, `cli` | Auth/contract transport, process startup/exclusion/terminal coordination, command composition | Browser-side authority, automatic migration or implicit Run. |
| `web` | Accepted REST resources, exact subscriptions, ephemeral selection and safe presentation | Durable currentness, mutation admission, provider context or inferred liveness. |

Deployment supplies external LXC isolation; Saivage neither creates nor verifies
it. Trusted in-container agents may run commands as root. Internal controls
simplify work, prevent accidents and preserve explicit API/data invariants, not
contain that principal. External authentication and outbound confidentiality remain
real boundaries. Ordinary deployments use bearer auth; disabled auth requires
deployment-owned trusted-origin isolation. Wildcard CORS is not authentication.
Bearer tokens remain header-only, never URLs; the UI has no token-login surface.

### Published package boundaries

Cross-package backend code uses owner-published roots or exact public entrypoints;
implementation imports within an owner stay local. Contracts/schemas retain their
bottom-layer prohibitions even through a public surface. Agents and runtime do not
import one another; workspace does not import runtime; server does not import boot.
Only boot imports server across packages, still through an admitted public surface.
Redaction primitives depend across packages only on schemas/contracts.

The exact reviewed leaf set is in `scripts/check-import-boundaries.cjs`:
`agents/{execution,tool}-api`, `cards/{status,store}-api`, `contracts/tool-api`,
`mcp/{manager,tool}-api`, `persistence/session-api`, `server/server-api`,
`tools/{execution,prompt,tool}-api`, `utils/prompt-api`, the sole runtime entry
`runtime/runtime-api`, and exact server-only `schemas/round-id-server`.
Terminal `.ts`/`.js` identify the same entry, not arbitrary neighboring/nested API
leaves. The round-ID generator is not exported from the browser-safe schema root.

`application/index.ts` publishes composition/read models/preparation; shared
freshness/intervention/lifecycle declarations belong to contracts. Agent execution
ports publish routing/invocation/exchange projection, tool ports the audited runner;
cards status ports expose pure lifecycle/permission predicates without loading
CardService. Runtime remains one consumption-curated aggregate, not newly split
facades. The boundary baseline is zero offending occurrences and an empty-array
digest. The shared scanner selects one rule per import/export occurrence, in
precedence contracts, schemas, redaction, agents→runtime, runtime→agents,
workspace→runtime, server→boot, server import, cross-package deep import; the digest
uses sorted path/rule/target tuples, retaining duplicate occurrences. It is not an
acyclic-module or complete-JavaScript-syntax proof. Type-only imports erase;
value reexports create evaluation edges. Residual application/runtime/tools cycles
are accepted and tested at relevant first entries, not promised universally safe.

## Startup: select, compile, admit, bind, listen

```text
CLI StartInputs → canonical root + bound lifecycle exclusion
  → selected environment/YAML → structural workflows
  → optional first publication + strict current generated-state admission
  → server composition/live bindings → owned services + terminal registrations
  → bounded configured-global settlement
  → Supervisor startup card-chain settlement (execution stays stopped)
  → outbound MCP reconciliation/install → external Analyst listener
  → operator HTTP listen → published lock control endpoint
```

`src/cli.ts` parses command-specific options once, rejects duplicate singletons and
passes typed `StartInputs`; boot does not reparse argv. Root precedence is CLI,
environment, cwd; config is CLI, environment, selected-root default; host/port are
CLI, environment, YAML, defaults. Each chain selects the raw source before
validating it. Token, log level and Node environment remain environment-owned.
`boot/app.ts::startApp` creates the terminal coordinator and acquires exclusion
before environment and generated effects,
narrows the lock to immutable `{pid,startedAt}` and injects it. A post-listen TCP
observation supplies the announced bound address, not delegation authority or proof
of reachability; lock endpoint publication is separate.

The early coordinator/lock cleanup registration is not live service composition.
After optional publication and canonical admission, `createServerServices` binds
workflows, creates Fastify and application/integration owners and registers their
admission/cleanup hooks. It settles configured globals, starts Supervisor recovery,
reconciles/installs outbound MCP, then listens on optional external Analyst MCP.
Server composition registers operator routes/live sync before HTTP listen; boot
publishes the lock endpoint afterward. This is not an all-validation-before-writes
transaction: the lock, first-root prefix, permitted admission tail truncation or
earlier settlement can remain after a later failure. No rollback or speculative
restart loop follows. [Startup diagnosis](../runbook/diagnosis.md#startup-does-not-reach-readiness)
distinguishes the failing boundary.

### Structural compilation and live binding

`ResolvedConfigAuthority` reads and parses YAML, interpolates its ordinary values
(preserving [literal data](../reference/configuration.md#owners-and-selected-input)),
then strictly decodes source config, resolves
omitted `card_types` to the complete classic map (no per-key merge), validates the
required effective map and calls `compileProjectWorkflows`. Deleted selectors and
old model shapes fail, not normalize. The same decoder serves mutation
preconditions without compiling current graphs; a correcting candidate is fully
compiled before replacement. Reconfigure publishes next-start YAML and returns
`requires_restart:true`, never installs it into this process. Load warnings are
immutable advisory strings; boot/offline CLI own redacted stderr output, REST its
warning array, without diagnostic reload or probes.

Compilation has no credentials, network, MCP, process or generated-state effects.
It resolves named agents/tool references/model order, records/globs/gates,
prompts/initializers, entry/node/edge declarations, child permissions and
descendant context. It validates reachability, terminal paths, source requirements
for exports, promotion reachability and transitive child context closure, then
publishes one immutable semantic state table per type. States are ready, lifecycle
entry, node and terminal; each transition has one target ID and semantic variant,
not a duplicate destination/node index. Entries are BACKLOG/CHANGED/BLOCKED/STOPPED;
terminals DONE/FAILED/BLOCKED. Result outcomes and runtime execution failure/block
edges remain distinct. A card selects by immutable type, not init profile or role.

After canonical admission, `bindRuntimeWorkflows` binds the
[specified participant set](../spec/system-specification.md#capacity-arithmetic-and-frozen-preparation).
It installs bindings beside the same tables, using local
structural Router/Registry ports, preserving ordered candidates and complete
capability requests. It retains maximum positive usable input `floor(U*C)-O` for
capacity-eligible candidates without credential/network probes. External-only mode
omits internal Analyst model binding, not its policy/index/evidence requirements
or card participation. Invocation later binds scopes, not source configuration.

### Templates and prompt closure

`config/system-templates/registry.ts` explicitly registers classic, classic-typed
and paad-typed complete frozen configs. There is no scan/loader/manifest.
`createClassicConfig` constructs fresh typed declarations then freezes once;
`OVERSIGHT_ALLOWED_TOOL_NAMES` is the shared contracts-owned allowlist. PAAD reuses
typed config, not runtime inheritance. Config-absent init materializes the selected
complete prompt closure/marker and YAML last; existing config preserves them.
Runtime follows the instance, not the selected init-profile label. The default
bundled prompt/card-type source remains classic where the instance omits overrides.

The compiler exact-selects project-card/project-shared/bundled-card/bundled-shared
hosts and direct fragments. Global scope uses shared tiers only. It freezes role
tokens and eagerly renders process text; a typed `global` card is not a global
host. Packaging compiles each template standalone and checks exact physical
source/package closure, classic-family shared bytes and PAAD's five explicit
differences. Compiled composition runs through build, not routine alone.
[Prompt handling](./prompts.md) owns host tokens, declaration retention,
customization and prepared-versus-historical explanation.

### Canonical admission before readiness

First publication requires all four generated roots absent. Existing state is
admitted through exact project head/selected ordinary artifact and bootstrap
record selection; partial/old/mixed state fails, never probes or reconstructs.
Init validates/compiles and binds identity/exclusion before generated admission;
the bootstrap owner publishes complete root/card sessions and then required global
Analyst index. Failure can leave a strict partial publication, not an implicit reset.

`current-generated-graph.ts` traverses linked current cards, validates active
dependencies and compiled parent/type membership, and stops at retained tombstones
before workflow/session/record admission. It reads required Analyst and each
card's distinct configured-agent indexes deterministically, then app log, required
session evidence, optional established Oversight evidence, current conversations
and configured records. Bootstrap authority is required; optional record heads are
not created. Empty valid indexes pass; missing required indexes fail. No old card
predecessors or unrelated namespaces are scanned. Current JSON documents have no
torn-tail permission. Broader consumed stopped-card JSONL remains strict, with
owner-local validated current-tail truncation where permitted. Server composition
separately consumes established Oversight current history before readiness.

Selected configuration is not a record of the previous graph. Required indexes
detect some identity changes, not same-agent node removal or every reused index.
Reached active cards, including non-tombstoned DONE/FAILED, still participate in
identity adoption. Never-used unpublished Oversight is different from replacing
known published Oversight. [State adoption](../runbook/state-adoption.md#participating-identity-changes)
owns the operator decision, not a startup fingerprint or session scan.

## Activation and node execution

```text
explicit Run / exact parent-bound child activation
  → Supervisor owner + lease → running publication → ready CardProcess activation
  → NodeExecution common resources → AgentExecutor OR invokeOperation
  → common acceptance/record close → accepted edge or terminal winner
  → natural card outcome publication → optional advisory hook → join/release/delivery
```

### Supervisor and exact authority

Supervisor owns one activation map, singular halt identity and guarded synchronous
`ownershipTransition`. Plain `CardActivationOwner` phases are prepared_root,
child_admission, active and settling. The transition changes in-memory phases,
relationships, currentness, run/gate/leaf/winner state and coherent invalidation;
I/O, abort delivery and joins occur outside it with exact identity checks after
awaits. Durable running without an exact live owner fails. No owner repository,
factory, queue, generation or second authority exists.

Each processor is ready before owner visibility and starts only after known running
publication. Run installs prepared root before recovery/publication; startup has
no activation owner. Child work enters only through an exact-parent
`PlannerChildControlPort` and invocation lease; provider code cannot choose parent
authority. Same-lease joins perform no target I/O. Dependency/status denial precedes
owner/processor creation. Natural release removes the exact relationship/map owner
before caller delivery. Root natural settlement requires no owned children and the
strict durable chain `[project]` before publication, with no post-publication scan.

`CardProcessActor` is the one narrow BaseActor micro-actor and owns graph position,
accepted-by-node activation memory and task/consumer joins. Unexpected nonterminal
events/start-entry/actor-main invariants latch `InternalActorError`, reject waiters
and notify the exact Supervisor owner once, never restart the pump. Ordinary task
failure instead uses code-owned `execution:failed`. Node ordinals begin at 0 and
accepted re-entry increments once. Tracker and consumer ownership remain distinct
from provider invocation lifecycles; joins snapshot current work/deliveries, and
failure precedence is pre-join cleanup, LLM order, tracker, lifecycle.

### Agent path and shared acceptance

`NodeExecution` owns record preparation, descendant snapshots, promotion,
notifications and terminal claim. `AgentExecutor` owns selected role/tools/full
node/parent preparation, the real conversation loop, corrections and finalization.
Record modes/globs remain conjunctive: clean, continue/updated and selected
initializers require direct write; edit/Webfetch does not substitute. Entry performs
initializer/clean/continue work then captures actual head UUID/revision baselines.
Updated acceptance requires a different UUID and greater revision; effective
baseline0/draft0/empty content is ineligible.

Reviewer context/snapshot uses one call-local root-inclusive subtree projection,
preserving each card and record head UUID/revision plus accepted entry/version.
Acceptance independently rereads it. A stale review discards written drafts,
reprepares clean requirements, captures refreshed context and corrects the same
node under original entry baselines. This is not an atomic filesystem snapshot or
remembered admission. The one joint 16-rearm budget covers malformed/plaintext
results, pending notifications, stale context, record and other corrective causes.

Acceptance checks records/descendants/freshness/promotion before terminal claim,
then closes required records in declaration order and other activation-written
records by sorted name. Only returned immutable close projections supply URLs,
transition evidence and exports. Nonaccepted graceful finalization discards owned
drafts; correction retains them. First finalization failure stops at committed
prefix; uncertainty permits no next close/cleanup. Crash-lost free-draft ownership
is not recovered by discovery. Result promotion (`current`/reachable `latest_node`)
is separate from terminal-source record exports; no prior activation memory is
recreated on STOPPED.

Shipped project assessment uses ordinary graph edges and status continue/updated
gates: classic-shared specializes project plan/recover/review into
`assess-completion`; goals retain notification handling. Reviewed completion can
promote Reviewer result while exporting Planner assessment status and immutable
review citation. It is not a natural-language objective checker. Typed architecture
likewise uses component then system review as clean cycles of the same record,
passing immutable accepted URLs; successful system review promotes accepted draft.
Typed test coverage-ready routes to verify, the sole successful terminal owner.
Other typed retries/research/data distinctions are selected instructions, not
template-aware runtime branches or persisted phase machines.
Prepared [role/node guidance](prompts.md#convergence-within-existing-role-decisions)
directs explicit result submission after current obligations, not readiness-only
status editing or waiting for downstream acceptance. Replan returns reconciled
remaining work to planning; native source_ready requests verification and saved-node
continuation, not product approval. Existing record, resource, pending-context and
exact reviewed-source candidate checks still own acceptance; prose adds no gate.

### Action path, output and advisory hooks

The explicit code-quality plugin supplies three contract1 actions through the same
finite owner. One packaged child imports native analyzer/config code; it emits
complete JSON to the host-owned capture and writes no artifact files. The owner
admits source paths for the actual caller, consumes only the settled host-selected
capture, then publishes fresh exact invocation artifacts synchronously. Publication
uncertainty reaches the existing fatal boundary; no child-side publication protocol,
registry or cleanup is added. Returned-text report bytes remain private until normal
NodeExecution output acceptance. Native tool grants are not implied by registration.

`operation-contract.ts` explicitly compiles builtins or declared plugins with
qualified identity/contract version and reserved namespace checks. It is not a
dynamic plugin service. The shared schema-level operation identity owns the same
qualified grammar for compilation, lifecycle, execution evidence and API projections.

Execution envelope3 also has logical native start/finish and sequential command
start/finish rows owned by GitWorkflow. These carry actual native bindings and completed observations,
not action descriptors or provider turns. The existing complete execution reader
validates associations and selects exact captures/private-index paths for work GC.
Incomplete attempts authorize no continuation. Evidence publication uncertainty
crosses the application fatal boundary before native follow-up or cleanup. This
contract does not enable ON before Supervisor lifecycle integration is complete.
Operation declarations select `null`, `command-stdout` or `returned-text` output
and exact artifact paths from validated configuration plus host invocation UUID.
The private run result separates completed bytes from flat routable values; it
does not confer record-write authority. `operation-routing.ts` resolves literal/factual/typed
predecessor inputs and validates strict bounded fields; first matching case owns
routing. It does not evaluate expressions, merge sources or replay log values.
The card `invokeOperation` wrapper appends entry/spawn/finish evidence. The shared
finite execution body owns the direct scope, actual process attribution, path
admission, return validation, exact declared artifact observations and completed
output. It takes no workflow binding or required card identity; a non-card caller
does not fabricate a card log or activation. Invalid
post-effect results are engine failures, not retry/no-effect outcomes. Actions
have no fake agent/session/tool call. Ordinary continue/exists uses accepted records.

Only a compiled output-declaring action node's `output_record` grants direct acceptance into its
one declared nonbootstrap continue/updated record. Entry rejects drafts/captures
head baseline; after direct cleanup, command-stdout requires absent group+EOF+no
stdout error before one exact host-selected capture read (at most 1 MiB + 1 byte).
Returned-text uses separately validated copied bytes, never a plugin-selected
capture path or invented process. Strict UTF-8 preserves BOM/CRLF/trailing bytes;
NUL, empty/whitespace, oversized/nonregular capture fails. Cancellation/currentness
is checked before synchronous ordinary `acceptRecord`. Accepted format 4 embeds independent
content and exact action/output provenance; equal text may advance version. Shell nonzero,
signalled or timed-out complete captures can publish factual reports; later gate
failure does not undo them or turn them into workflow approval. Current/history/VFS
read the accepted artifact, not capture/log. The shared author union includes
agent, external-agent, runtime bootstrap/repair and action-output; typed observations
remain author-free and draft/baseline `content_author` is null.

`after_activation_commit` runs only after natural done/blocked/failed publication
and owner/halt recheck. Supervisor passes the returned committed snapshot/artifact,
not reread state or cleared node input. The tracked advisory run joins its matching
consumer before release. Ordinary hook failure preserves outcome; containment and
storage failures retain failure authority. Recovery/Stop/cancel/reopen/record edits
do not dispatch hooks. Actions/hooks share one processor-local nonagent in-flight
binding through raw operation, finite cleanup and matching delivery. Stop/cancel
selects cancel-and-settle before abort, even after process exit; no successor runs.

## Caller-specific tools and Analyst operations

Names do not grant authority. Provider-owned catalogs define immutable identities,
descriptions and scope-aware schema factories; compilation preserves ordered
references, real binding supplies vocabulary/parent/process context. Effective node
selection removes create only when no permitted child creation remains. The bound
surface supplies actual definitions/capabilities; generated strict `emit_result`
is appended separately. Exact object/schema rejection enters the shared correction
loop; terminal settlement parses accepted, error or pending-notification variants.

`invokeToolForLlm` is the required complete LLM-context boundary; only
`ConversationLLMActor.toolInvocationContext` constructs that context. External
