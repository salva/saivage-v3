# F05 — Plan Review r1

1. **Batches (a)–(g) are not independently committable/testable.**
   - What's wrong: the plan promises design-order, one-commit batches with a compiling tree, then explicitly makes batches (a) through (g) interdependent and accepts broken `npx tsc --noEmit` plus deferred test rewrites. That prevents an implementer from executing the plan under the requested “each batch independently committable + testable” constraint.
   - Verified evidence: the approved design requires “Strict batched order — each batch leaves the tree compiling against the new contract” in [02-design-r4.md](02-design-r4.md#L584). The plan itself claims “Tree compiles at the end of every batch” in [03-plan-r1.md](03-plan-r1.md#L37), but batch (a) says `npx tsc --noEmit` should “expect failures” in [03-plan-r1.md](03-plan-r1.md#L88), says “This batch BREAKS the build” in [03-plan-r1.md](03-plan-r1.md#L93), and says batches (a) through (g) “only restore `npx tsc --noEmit` together” in [03-plan-r1.md](03-plan-r1.md#L95). The same pattern continues when batch (b) expects the “same failures” in [03-plan-r1.md](03-plan-r1.md#L121), batch (e) defers broken existing invoke tests to batch (k) in [03-plan-r1.md](03-plan-r1.md#L238), and batch (f) cannot run its named analyst tests until fixtures are rewritten later in [03-plan-r1.md](03-plan-r1.md#L270).
   - Required change: re-batch the implementation so every batch ends with a green `npx tsc --noEmit` and the batch-owned tests passing. Remove all “expected failures”, “typecheck-only-of-new-modules”, and “fixtures rewritten later” validation steps. If the contract flip cannot be safely split without shims, make the affected contract/consumer/test rewrites one coherent batch/commit instead of committing broken intermediate states; keep the approved design’s zero-backward-compatibility rule intact.

2. **The plan omits required source migrations for the legacy persisted `toolCalls` wrapper readers.**
   - What's wrong: the approved design requires rewriting the runtime/session source readers that parse legacy `{ toolCalls: [...] }` rows, but the plan only names their tests. As written, an implementer can finish the plan while leaving old wrapper-reading code alive in production source, violating zero backward compatibility and “delete dead code.”
   - Verified evidence: the approved design explicitly lists [src/agents/session-persistence.ts](../../../../src/agents/session-persistence.ts#L379-L420) and [src/runtime/runtime.ts](../../../../src/runtime/runtime.ts#L234-L264) as source readers to rewrite in [02-design-r4.md](02-design-r4.md#L371-L372), and repeats that migration in implementation step 11 in [02-design-r4.md](02-design-r4.md#L596). Current source still parses `.toolCalls` directly in [src/agents/session-persistence.ts](../../../../src/agents/session-persistence.ts#L380-L384) and iterates it in [src/agents/session-persistence.ts](../../../../src/agents/session-persistence.ts#L415); [src/runtime/runtime.ts](../../../../src/runtime/runtime.ts#L239-L255) does the same in two loops. The plan’s migration list only mentions [tests/agents/session-persistence.test.ts](../../../../tests/agents/session-persistence.test.ts#L328) / `#L337` in [03-plan-r1.md](03-plan-r1.md#L413), and no batch lists the production source files above as modified.
   - Required change: add the production-source migration for [src/agents/session-persistence.ts](../../../../src/agents/session-persistence.ts) and [src/runtime/runtime.ts](../../../../src/runtime/runtime.ts). Both should consume one persisted `ToolCall` per row via `parseToolCallMessage`, reject legacy wrapper rows with `LegacyMessageShapeError` rather than silently bridging them, and update the final grep/static checks so source-level `.toolCalls` wrapper readers cannot survive.
