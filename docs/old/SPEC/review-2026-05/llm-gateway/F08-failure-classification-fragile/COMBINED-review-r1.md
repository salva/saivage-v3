   b. Impact: following the plan literally leaves Batch 1 uncompilable, or forces temporary compatibility exports for the deleted classes. The latter violates the stated zero-backward-compat/dead-code-deletion rule, and the former violates the required green checkpoint. It also undermines the rollback note claiming Batch 1 typed gateway throws are handled by `unwrapFailure` on the old policy ([COMBINED-r1.md#L276](COMBINED-r1.md#L276)); the old policy has no `unwrapFailure` branch.

   c. Required change: move the `InvocationRecoveryPolicy` rewrite and every remaining `llm-errors.ts` consumer rewrite into the same green batch as the hierarchy deletion, or keep the old hierarchy until the batch that rewrites all consumers. The fixed batch must explicitly cover the current non-gateway importers (`LlmProviderGateway` capability mismatch, chat/Codex stream parser errors, `recordResponseError`, and `LlmIntentResolver`) and keep the final `grep`-zero gate. Do not preserve compatibility classes as shims.
