## Review Summary

This review focused on actionable defects and consistency risks rather than broad style preferences. The codebase has a solid typed foundation, broad tests, and the recent goal-level planner/executor/reviewer architecture is now mostly reflected in runtime code. The remaining issues found in this pass are concentrated in security boundaries, project-root isolation, and stale operator/agent-facing text.

## Findings

### 1. Agent file reads lack project-root containment

`readProjectFileAtomic(projectRoot, relativePath)` strips a leading `./`, checks sensitive-file names, and then joins the requested path to `projectRoot`. It does not reject absolute paths or `..` escapes before reading. This function is documented as the main file-read integration point for agents, so it must enforce containment even if current call sites are limited.

Impact: A future or existing agent tool using this helper could read outside the managed project root.

Plan: Resolve `projectRoot` and requested paths, reject absolute requested paths, reject paths whose normalized relative path escapes the root, and add regression tests.

### 2. Analyst tool schemas still advertise removed `plan` card type

`ANALYST_TOOL_DEFINITIONS` still describes `plan` as a non-terminal card type and as a valid filter value. The runtime/card store now rejects plan-card creation and stores planning state on goals.

Impact: The analyst LLM may request invalid tool calls, causing avoidable API/tool failures and confusing users.

Plan: Update the tool schema text and add tests that the advertised card types do not include `plan`.

### 3. Analyst handlers are global singletons not scoped by project root

The HTTP chat routes and WebSocket handler each lazily create a module-level `AnalystHandler`. If the same Node process creates servers for different project roots, the later server can reuse a handler bound to the earlier root.

Impact: Tests, embedded deployments, or future multi-project operation can leak state/actions across project roots.

Plan: Replace singletons with per-project-root handler maps in both modules.

### 4. Authored docs contain stale or broken operator-facing references

`docs/index.md` still describes the old `Planner -> Manager -> Workers` architecture in the introduction even though its architecture section is correct. `README.md` links to uppercase documentation filenames that do not exist on this Linux filesystem.

Impact: New operators and agents reading docs receive contradictory architecture guidance or broken links.

Plan: Update the intro to planner/executor/reviewer and fix README links to existing lowercase docs files.

### 5. Generated docs output is noisy in git status

`docs/.vitepress/dist` has many changed/deleted hashed assets from builds. This is generated output, so it should be regenerated by the validation step rather than hand-edited.

Impact: Review noise and possible stale served docs if build artifacts are not refreshed after authored docs change.

Plan: Run `npm run docs:verify` or root build after fixes; do not manually patch generated dist files.

## Replan Update: Backend Validation Failures

The first full backend validation pass exposed additional stale contracts and one runtime trigger bug:

- Schema fixtures still contained `card-plan.json` and diary/review records using `plan_card_id` even though goal-level planning now requires valid card types and `goal_card_id`.
- Card-store regression tests accidentally asserted that `research` cards should be forbidden instead of exercising the removed `plan` type.
- An OAuth profile test depended on `/work/saivage-v3` being present, which is only true in the container deployment and should not be required for host tests.
- Continuous improvement checks only ran through backlog auto-dispatch, so `continuousImprovement: true` with `autoDispatchBacklog: false` never invoked project-level improvement.
- A supervisor force-cancel integration test advanced fake timers across many periodic intervals while trying to test only the force-cancel timeout.

Remediation applied:

- Replaced the stale plan-card fixture with an architecture-card fixture and updated diary/review fixtures to goal-level fields.
- Restored explicit plan-card rejection messages in `CardStore` before schema validation.
- Made the OAuth profile suite independent of container-only credential mounts.
- Restored continuous-improvement startup checks when backlog auto-dispatch is disabled.
- Adjusted the supervisor integration test interval so the force-cancel timer can be tested deterministically.
