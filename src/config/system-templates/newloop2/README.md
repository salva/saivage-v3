# newloop2 — explicit goal review loop

Fresh opt-in selection: `saivage init --profile newloop2` on a config-absent
project. Default remains classic. Native Git remains OFF; shared capabilities,
named agents, tools, routes and runtime are unchanged. This is not a switch for
retained projects: matching outer formats do not make different workflow identities
interchangeable. No migration, reset, deployment or Run is implied.

Project/goal fresh path: `frame-plan → alignment → deliver → integrated-acceptance
→ debt-assessment → DONE`; root inserts `objective-assessment` after delivery.
Planner authors expanded functional analysis/plan separately from its brief,
commissions production children and reconciles the complete outcome. Reviewer
challenges alignment, independently accepts the integrated result and then judges
relevant structural debt. A justified no-change debt verdict is sufficient.
Refactoring returns through framing/alignment, production, acceptance and debt;
unrelated cleanup is not a completion requirement. No direct planning completion.

BACKLOG starts framing. CHANGED/BLOCKED/STOPPED start `resume-assess`; STOPPED adds
uncertainty-aware recovery context. Route the earliest materially affected
obligation, preserving applicable evidence, not an encoded saved phase or automatic
restart. FAILED needs supported reopen first. Only the current final review is
promoted. Pending final notifications return to the designated Planner (architecture:
Executor) assessment; they are not discarded as successful closure.

Typed code/test/research/data/architecture stages remain asset-specific. Code,
research, data and architecture gain selective Executor assessment; test uses
diagnose, doc/ops use their distinct execute tasks. Leaves cannot create children.
Architecture review-only reentry promotes the current system review, not an absent
activation-local draft result. Parent integrated acceptance remains necessary.

Every node receives full accepted bootstrap independently plus conditional own
status and, where declared, accepted review. Review nodes also receive effective
draft. Only the required record is initialized; updated gates reject scaffolds or
unchanged records. Feeds can be suppressed/excerpted; read missing exact history
through selected tools and carry useful immutable citations before replacing review.
Descendant freshness on the three project/goal reviews includes selected child
status/bootstrap; own feeds are not an automatic own-record tuple fence or workspace
certification. One Planner and one distinct Reviewer session are reused, not fresh
independent reviewers per stage. Reviewer is instructed not to repair judged assets,
but shared workspace write capability is unchanged. Node-local delegation is not
enforced: graph ordering does not prohibit all early production effects.

Parents can accept eligible inactive immediate-child briefs through existing grants;
self/grandchild briefs, active targets and open nonself drafts refuse. Direction or
metadata does not amend requirements. BLOCKED amendment changes to CHANGED, not
running; activation and outer Run remain separately admitted. No authority-engine
change or resolution of separate authority/security qualification is claimed.

Original local wording draws conceptual input from [PAAD v2.1.0](https://curtispoe.org/paad/)
(read November 10, 2026): reality-grounded premise challenge, bidirectional intent
coverage, alignment, verified findings and structural quality. No mandatory human
approval, specialist count, coverage quota or Git ritual is imported. Existing
newloop remains its eight-delta prose-only typed variant; this standalone deeply
frozen configuration has its own complete physical selected prompt closure.

Extra goal handoffs trade overhead for explicit review opportunities. Compiler,
scripted actor/tool, CLI, package and composition tests qualify paths and existing
gates, not model insight, compliance or improved output quality. See
[validation](../../../../docs/validation.md) and
[the specification](../../../../docs/spec/system-specification.md#newloop2-explicit-review-loop).
